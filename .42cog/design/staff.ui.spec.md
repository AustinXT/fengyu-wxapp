## 1. 设计系统

### 1.1 审美方向：工业实用

紧凑信息密度、网格对齐、低彩度中性背景。品牌红 `#C0322A` 仅用于关键操作入口和数据高亮，不做大面积铺色（工作台分成卡片例外——作为唯一的品牌色块建立视觉锚点）。

### 1.2 配色方案（白红主题，品牌统一）

所有色值已在 `app.wxss` 中定义为 CSS 变量，页面级 WXSS **必须引用变量**而非硬编码色值。

| 用途 | 变量 | 色值 | 说明 |
|------|------|------|------|
| 主色 | `--color-primary` | `#C0322A` | 中国红，按钮/Tab/高亮/FAB |
| 主色浅 | `--color-primary-light` | `#FFF0EE` | 选中态背景/提示区 |
| 主色深 | `--color-primary-dark` | `#9B1E14` | 渐变终止色 |
| 成功 | `--color-success` | `#3D8A5A` | 已确认/已支付 |
| 警告 | `--color-warning` | `#D4820A` | 待确认/待处理 |
| 错误 | `--color-error` | `#D94040` | 支付失败/危险操作 |
| 信息 | `--color-info` | `#5E8BB3` | 服务中/进行中 |
| 主文本 | `--color-text-primary` | `#1A1A1A` | — |
| 次要文本 | `--color-text-secondary` | `#666666` | — |
| 提示文本 | `--color-text-hint` | `#999999` | placeholder/辅助说明 |
| 边框 | `--color-border` | `#E8E8E8` | — |
| 页面背景 | `--color-bg-page` | `#FAFAFA` | — |

**状态徽章**（低饱和背景 + 对应深色文字）：

| 状态 | 变量 | 背景色 | 文字色 | 适用场景 |
|------|------|--------|--------|----------|
| 待处理 | `--color-badge-pending` | `#FFF3E0` | `#D4820A` | 待确认/待支付/待分配 |

| 错误 | `--color-badge-error` | `#FFEBEE` | `#D94040` | 支付失败/已取消 |

```

```

| 层级 | 字号 | 字重 | 行高 | 用途 |
|------|------|------|------|------|
| 页面标题 | 36rpx | 700 | 1.3 | 弹层标题、独立页标题 |
| 区块标题 | 30rpx | 600 | 1.4 | section-title、卡片标题 |
| 正文 | 28rpx | 400 | 1.5 | 列表项文字、表单文字 |
| 辅助 | 24-26rpx | 400 | 1.4 | 时间/描述/次要信息 |
| 小字 | 22rpx | 400-500 | 1.3 | 标签/角标/状态徽章 |

### 1.4 间距系统

| 变量 | 值 | 用途 |
|------|------|------|
| `--spacing-page` | 32rpx | 页面水平内边距 |
| `--spacing-card` | 24rpx | 卡片内边距 |
| `--spacing-tight` | 16rpx | 紧凑间距（列表项间、标签内距） |

**卡片间距规则**：
- 卡片外边距：`margin: 24rpx 32rpx 0`
- 卡片圆角：`16rpx`（统一）
- 卡片阴影：`0 2rpx 12rpx rgba(0,0,0,0.06)`（轻微，非 AI 模板式过度阴影）

### 1.5 Vant 主题覆盖

已在 `app.wxss` 中通过 CSS 变量统一覆盖 Vant 组件主色为 `#C0322A`，包括：
- Button、Tab、Tag、Checkbox、Radio、Search、Loading、Sidebar

新增页面**无需重复覆盖**，直接使用即可。

## 3. 通用组件规范

### 3.1 状态标签（.status-tag）

已在 `app.wxss` 定义全局样式，5 种变体：

```wxml
<text class="status-tag status-tag--pending">待确认</text>
<text class="status-tag status-tag--success">已支付</text>
<text class="status-tag status-tag--progress">服务中</text>
<text class="status-tag status-tag--done">已完成</text>
<text class="status-tag status-tag--error">支付失败</text>
```

**状态→变体映射**：

| 状态文字 | 变体 class |
|---------|-----------|
| 待支付/待确认/待确认收款/待分配/待服务 | `--pending` |
| 已确认/已支付 | `--success` |
| 服务中 | `--progress` |
| 已完成/已关闭/已取消 | `--done` |
| 支付失败 | `--error` |

### 3.2 价格组合（.price-group）

已在 `app.wxss` 定义：

```wxml
<view class="price-group">
  <text class="price-symbol">¥</text>
  <text class="price-integer">1,999</text>
</view>
```

金额/价格统一使用品牌红 `--color-primary`。

### 3.3 三态视图（强制要求）

所有数据页面**必须实现三态视图**，严格互斥：

```wxml
<!-- 加载态 -->
<view wx:if="{{loading}}" class="loading-wrap">
  <van-loading type="spinner" color="#C0322A" />
</view>

<!-- 空态 -->
<view wx:elif="{{!list.length}}" class="empty-wrap">
  <van-empty description="暂无数据" />
</view>

<!-- 内容态 -->
<view wx:else>
  <!-- 内容 -->
</view>
```

### 3.4 底部固定栏 + 安全区

所有底部固定操作栏必须处理安全区：

```wxss
.bottom-bar {
  position: fixed;
  bottom: 0;
  left: 0;
  right: 0;
  padding: 16rpx 24rpx;
  padding-bottom: calc(16rpx + env(safe-area-inset-bottom));
  background: #FFFFFF;
  border-top: 1px solid var(--color-border);
}

/* 内容区底部占位 */
.bottom-placeholder {
  height: calc(120rpx + env(safe-area-inset-bottom));
}
```

注意：细边框使用 `1px` 而非 `1rpx`（高清屏兼容）。

### 3.5 卡片组件模式

```wxss
.section-card {
  margin: 24rpx 32rpx 0;
  background: #FFFFFF;
  border-radius: 16rpx;
  overflow: hidden;
  padding: 24rpx;
}

.section-header {
  display: flex;
  align-items: center;
  justify-content: space-between;
  margin-bottom: 16rpx;
}

.section-title {
  font-size: 30rpx;
  font-weight: 600;
  color: #1A1A1A;
}
```

### 3.6 角色权限 UI 控制

店长专属操作通过 `wx:if="{{isManager}}"` 控制可见性：

```wxml
<!-- 仅店长可见 -->
<van-button wx:if="{{isManager}}" type="primary" bindtap="onConfirmOffline">
  确认收款
</van-button>
```

权限判断数据来源：`app.globalData.permissions`，工具函数在 `utils/role.ts`。

### 3.7 Vant 组件注意事项

- `van-toast` / `van-dialog`：必须在 WXML 中放置对应节点
- `van-tab`：`color="#C0322A"` 统一主色
- `van-cell-group`：列表项首选，自带分隔线和箭头
- `van-empty`：空态统一使用
- `van-loading`：加载态统一使用 `type="spinner" color="#C0322A"`

### 3.8 图标策略

优先级：**van-icon** > **Icons8 图片** > **本地 PNG**

Icons8 格式（如需使用）：
```
https://img.icons8.com/ios/100/{color}/{icon-name}.png
```
统一 `ios` 线框风格。引用后**必须下载到 `images/` 目录**。

### 3.9 管理层视图扩展规范

管理层视图（manager / 总部 / 市场 层级账号视图，共 6 页：`pages/mgmt-dashboard`、`pages/sales-data`、`packageMgmt/mgmt-traffic-stats`、`packageMgmt/mgmt-product-cycle`、`packageMgmt/mgmt-customer-list`、`packageMgmt/mgmt-customer-detail`）在 §1 设计系统的基础上扩展以下规范。

#### 3.9.1 新增 CSS Token（已在 `app.wxss` 定义）

| Token | 值 | 用途 |
|-------|-----|------|
| `--radius-sm` | `8rpx` | 小角标 / chip / 规格标签 |
| `--radius-md` | `12rpx` | 行容器 / 筛选触发器 |
| `--radius-lg` | `16rpx` | **标准卡片**（dash-card / customer-card / treatment-card / refund-card 等全部统一引用） |
| `--radius-pill` | `999rpx` | 胶囊：type-tab 等 |
| `--shadow-card` | `0 2rpx 12rpx rgba(0,0,0,0.06)` | 卡片标准阴影（与 §1.4 一致） |
| `--shadow-card-soft` | `0 2rpx 8rpx rgba(0,0,0,0.04)` | 轻阴影（gift-card / refund-card） |
| `--gap-grid` | `16rpx` | 网格主 gap（卡片之间） |
| `--gap-grid-tight` | `8rpx` | 网格紧凑 gap（4 列指标） |
| `--color-divider-soft` | `#F0F0F0` | 行内细分割线，区别于 `--color-border: #E8E8E8` 卡片外框 |
| `--color-bg-warm` | `#F5F2EE` | 暖米色（规格标签 / customer-detail 多处复用） |

**禁止散落硬编码**：管理层 6 页 wxss 中 `#999/#666/#333/#fff/#f0f0f0/#f5f5f5/#fafafa/#ddd` 必须全部用 token 替换；Vant 组件 prop 中的颜色字符串（如 `<van-icon color="#999">`）属合理硬编码。

#### 3.9.2 复用组件（`miniprogram/components/`）

| 组件 | props | events | 用途 |
|---|---|---|---|
| `mgmt-stat-card` | `count`, `label`, `size: 'lg'\|'md'`, `variant: 'default'\|'primary'\|'success'\|'warning'\|'error'\|'info'\|'muted'`, `selected: boolean`, `unit: string`, `count-color: string`（覆写） | `tap` 透传 | 统一 KPI 卡片：count 大数字 + label 小标签，垂直布局，可点击/可选中 |
| `mgmt-period-picker` | `options: [{label, value}]`, `value` | `change` → `{value}` | 时间段筛选 chip 组（边框 + 红填充式，圆角 `--radius-sm`） |
| `mgmt-metric-tabs` | `options`, `value`, `columns: 3\|4` | `change` | 指标切换按钮组（3 列 / 4 列网格，灰底 + 红填充选中） |
| `mgmt-data-state` | `state: 'loading'\|'empty'\|'error'\|'content'`, `loadingText`, `emptyText`, `errorText`, `retryText` | `retry` | **整页/整段三态壳**，错误态自带"重试"按钮；slot 用于内容态 |

**特殊场景透传**：当业务规定的色值（如 customer-list 6 张统计卡的鲜亮绿 `#07c160` / 橙 `#ff8f1f` / 紫 `#a06abf`）与 spec 语义色不完全对应时，通过 `count-color` prop 透传字符串，避免视觉失真。

**不再造的组件**：`.status-tag--{pending,success,progress,done,error}`（已在 §3.1 全局类）已能覆盖管理层所有徽章场景，customer-detail 等不得再自定义 `.refund-type--*` / `.direction--*` 重复类。

#### 3.9.3 三态壳模式（强制）

管理层 6 页所有"整页/整段数据"必须使用 `<mgmt-data-state>` 包裹，**不得再写散落的 `wx:if="loading"` + 文字版"加载中..."/"暂无数据"**。错误态必须支持 `bind:retry`，由页面 ts 重新触发数据加载。

分页 footer 的小 loading（"加载更多 / 没有更多"）仍然手写 `<van-loading size="24rpx" />`，与三态壳分离。

#### 3.9.4 Sticky 筛选区与下拉刷新

- 6 页 `.json` 必须开 `"enablePullDownRefresh": true`，`.ts` 必须实现 `onPullDownRefresh()`，结束时调 `wx.stopPullDownRefresh()`。
- 时间段 chip / 指标切换 / 搜索框 / type-tab 的容器必须 `position: sticky; top: 0; z-index: 10; background: var(--color-bg-page);`，长列表滚动时持续可见。
- customer-detail 的 6 Tab 用 `<van-tabs sticky>` 自动吸顶。
- `onPullDownRefresh` 仅刷新当前可见 Tab 的数据（如 customer-detail 按 `activeTab` 路由），不无脑全量刷新。

#### 3.9.5 不强行对齐项（明确保留差异）

- **sales-data 的下划线 period chip**（嵌在白色卡片内的二级筛选）与其他页面的填充式 chip 是**结构性差异**，不强行用 `mgmt-period-picker` 替换。
- **customer-list 6 张统计卡的鲜亮色** 已通过 `count-color` 透传保留视觉，不强行映射成偏暗的 spec 语义色。
- **`tier-badge--{fan,iron,diamond}`** 的三色（粉丝灰 / 铁粉橙 / 黑钻金）由 `staff.pr.spec.md §3.14` 强制规定，保留硬编码并加注释。

**独立页面，无 TabBar。**

```

│         员工端                      │
```

- 页面中上区域品牌名（36rpx/700，品牌红）
- 按钮使用 `van-button type="primary"` 圆角胶囊
- 背景：纯色 `#FAFAFA`，不加渐变/插画

| 销售数据 | `pages/sales-data` | 业绩与实耗 + 业绩与品项 3 维度汇总 | `mgmt-data-state`，**保留下划线 period chip**（结构性差异，§3.9.5） |
| 客量数据 | `packageMgmt/mgmt-traffic-stats` | 5 Section：注册 / 客流 / 会员状态 / 经营 / 新会员 | `mgmt-period-picker`、`mgmt-stat-card` × N、`mgmt-data-state` |
| 品项数据 | `packageMgmt/mgmt-product-cycle` | 4 段表格：持卡 / 体验 / 新增 / 复购 | `mgmt-period-picker`、`mgmt-data-state` × 4（持卡 / 周期数据各自独立） |
| 顾客档案列表 | `packageMgmt/mgmt-customer-list` | 分页搜索（关键字 / 全量），50 条 / 页 | `mgmt-data-state` |
| 顾客档案详情 | `packageMgmt/mgmt-customer-detail` | 6 Tab：详情 / 日历 / 购买 / 持卡 / 赠送 / 退换；`van-tabs sticky` | `mgmt-data-state`（顶层）；`van-tabs sticky` 自动吸顶 |

**数据流**：scope（市场 / 门店）由 hub `mgmt-dashboard` 通过 `mgmt-scope-picker` 选择，路由参数透传到各子页（`scopeType` / `scopeId` / `scopeName`），子页只读不再展示 picker，页面内仅显示 `.mc-scope-bar` 提示条（背景 `var(--color-primary-light)`）。

**身份控制**：每页 `onShow` 调 `canAccessManagement()` 校验；其唯一前端依据是服务端下发的 `availableLoginLevels` 是否包含 `management`。服务端以 `data_center:dashboard` 和完整 scope 做最终鉴权，未获权账号重定向回 `/pages/workbench/workbench`。

## 5. 交互模式

### 5.1 加载态

| 场景 | 方案 |
|------|------|
| 页面首次加载 | `van-loading type="spinner" color="#C0322A"` 居中；管理层视图统一用 `<mgmt-data-state state="loading">`（§3.9.3） |
| 列表加载更多 | 底部 `van-loading size="24rpx"` + "加载中..." |
| 按钮操作中 | `van-button loading` 属性 |
| 下拉刷新 | **管理层视图全部启用**（`enablePullDownRefresh: true`）；门店视图按页酌情 |
| 加载失败重试 | 管理层视图统一用 `<mgmt-data-state state="error" bind:retry>`（§3.9.3） |

### 5.2 反馈

| 操作 | 反馈 |
|------|------|
| 创建成功 | `Toast.success('创建成功')` |
| 确认操作 | `Toast.success('操作成功')` |
| 参数错误 | `Toast.fail('xxx不能为空')` |
| 网络错误 | `Toast.fail('网络异常')` |
| 无权限 | `Toast('暂无权限')` + 路由拦截 |

### 5.3 确认弹窗（敏感操作）

| 操作 | 标题 | 描述 | 按钮 |
|------|------|------|------|
| 关闭订单 | 确认关闭？ | 关闭后顾客无法继续支付 | 关闭 |
| 确认收款 | 确认线下收款？ | 确认后订单状态变为已支付 | 确认 |
| 完成服务 | 确认完成服务？ | 完成后将扣减次数，不可撤销 | 完成 |
| 重置支付 | 确认重置？ | 订单将恢复为待支付状态 | 重置 |
| 审批解绑 | 确认同意解绑？ | 解绑后顾客将离开本店 | 同意 |
| 退出登录 | 确认退出？ | — | 退出 |

弹窗统一使用 `van-dialog`，确认按钮色 `#C0322A`。

### 5.4 空态

| 场景 | 展示 |
|------|------|
| 列表无数据 | `van-empty description="暂无数据"` |
| 搜索无结果 | `van-empty description="未找到匹配结果"` |
| 无待处理事项 | 正常显示 `0条`（不隐藏项） |

### 5.5 滚动与分页

| 页面 | 方案 |
|------|------|
| 工作台 | 自然页面滚动（内容固定，无分页） |
| 开单商品列表 | `scroll-view scroll-y`（需显式 height） |
| 订单/服务/预约列表 | `onReachBottom` 触底加载，`pageSize=20` |
| 顾客列表 | `van-search` + 列表（数据量小，不分页） |

## 7. 约束保障（UI 层面）

| real.md 约束 | UI 保障方式 |
|-------------|------------|
| 次数防超卖 | 完成服务按钮需确认弹窗；按钮 loading 防重复点击 |
| 价格快照不可变 | 订单详情中价格为只读展示，不可编辑 |
| 支付幂等 | 确认收款按钮操作后 disable + loading |
| 状态单向推进 | 操作按钮根据当前状态动态渲染，不显示越权按钮 |
| 后端统一鉴权 | 前端 `role-guard` 仅做 UI 提示，不做安全保障 |
| 组织域数据隔离 | 前端按 `boundStoreId` 请求数据，后端强制过滤 |

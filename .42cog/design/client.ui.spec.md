## 1. 设计规范

### 1.1 应用类型：原生微信小程序（Tab + 分包）

**判定依据**：顾客高频操作为浏览商品、下单支付、预约管理，典型的 Tab 导航 + 分包懒加载模式。主包 < 2MB，分包按业务域拆分（商品/订单/门店/预约/优惠券）。

### 1.2 审美方向：柔和粉彩 × 奢华精致

**判定依据**：
- 目标用户为美容院女性顾客，需温暖感与品质感兼顾
- 品牌色中国红 `#C0322A` 作为点睛，大面积留白保持呼吸感
- 通过渐变、阴影、圆角等细节传递高端美容院定位
- 不做满屏红色轰炸，红色仅用于 CTA 按钮、Tab 高亮、价格、品牌标识

### 1.4 字体策略

```css
font-family: -apple-system, BlinkMacSystemFont, 'Helvetica Neue',
             'PingFang SC', 'Microsoft YaHei', sans-serif;
```

通过**字重 + 字号 + 颜色**三维创造层次，不依赖不同字体族：

| 层级 | 字号 | 字重 | 颜色 | 用途 |
|------|------|------|------|------|
| 大标题 | 40rpx | bold (700) | `#1A1A1A` | 页面主标题（极少使用） |
| 标题 | 34rpx ~ 36rpx | semi-bold (600) | `#1A1A1A` | 区块标题、导航栏 |
| 正文 | 28rpx | normal (400) | `#1A1A1A` | 主体文本、列表内容 |
| 辅助 | 24rpx | normal (400) | `#666666` | 副标题、标签、说明 |
| 小提示 | 20rpx ~ 22rpx | normal (400) | `#999999` | 时间、备注、版权 |
| 价格整数 | 40rpx ~ 48rpx | bold (700) | `#C0322A` | 商品价格主体 |
| 价格符号 | 22rpx | semi-bold (600) | `#C0322A` | ¥ 符号 |
| 价格"起" | 22rpx | normal (400) | `#999999` | 起步价标识 |

### 1.5 布局策略

- **顶部导航**：白底 + 品牌 Logo（`images/logo.webp`）+ 门店选择器 + 扫码入口
- **底部 TabBar**：4 Tab（首页/预约/凤御馆/我的），选中色 `#C0322A`
- **卡片节奏**：统一 `24rpx` 内间距，`32rpx` 页面侧边距，卡片间 `24rpx` 间隔
- **视觉层次**：品牌红渐变仅用于头部强调区（如个人中心顶部、疗程卡头部），主体区域保持白底清爽
- **圆角规范**：卡片 `16rpx`，按钮 `44rpx`（全圆角胶囊），标签 `8rpx`，头像全圆

```
│  🛒 [badge: 3]              │
└────────────────────────────┘
```

**关键交互**：
- 门店选择器：点击跳转 `pagesStore/store-select`，切换门店清空购物车和缓存
- 搜索：跨分类即时过滤，预加载未缓存分类按名称匹配，结果替代商品列表区
- 金刚区：前 3 项跳转 `pagesShop/shop` 并滚动到对应分类；"我的疗程" → `pagesOrder/treatment-cards`
- 侧边栏：`van-sidebar`，product_kind 标题不可点（灰色分组头），子分类可点联动右侧
- 商品卡片：点击跳转 `pagesShop/service-detail?spuId=xxx`
- 购物车 FAB：仅 `cartCount > 0` 可见，badge > 99 显示 `99+`，点击跳转 `pagesShop/shopping-cart`
- SPU 分页：scroll-to-lower 500ms 防抖 + 模块级缓存（`categoryId` 为键）
- 扫码：`wx.scanCode()` → path 型 `navigateTo` / orderNo 型跳转 scan-pay

**三态视图**：
1. 加载态：左侧分类骨架（3 条） + 右侧卡片骨架（4 个矩形）
2. 空态：`van-empty` + "该分类暂无商品"
3. 数据态：商品卡片网格（两列）

**防连点**：按钮点击后 `loading` 态 + `disabled`，等待响应后恢复

| 家居产品 | "已交付"（支付即完成） |

**倒计时**：待支付状态显示 `MM:SS`，**倒计时只在后端下发 `expire_at` 时出现**——员工/店长开单的订单、以及已发起在线支付的订单不会被超时关闭，不给它们显示倒计时，状态区退为「请完成支付」（issue #215）。

计时基准与显示口径由服务端给（剩余毫秒 `expire_in_ms` + 东八区时刻 `expire_clock`），前端不拿设备时钟/时区推导；秒数用 `ceil`，最后一拍恰好落在截止点，**不会出现「剩余 00:00」却还能点支付**。

归零后的行为分四类（详见 `client.sys.spec.md` §9 的口径表）：走到零或权威剩余量被网络耗时扣光 → 清倒计时 + **关闭支付入口**（文案改「支付时限已到，正在确认订单状态」）+ 刷新一次；服务端明说「已过期但没关掉」→ 同样关闭支付入口；旧版本云函数的口径 → 每单只刷新一次、不关支付入口；墙钟被回拨 → 刷新但不关支付入口。成功刷新会解除支付入口的封锁 —— **除非那次响应是「已过期但服务端没关掉」**，那时继续封锁。

## 7. 交互模式

### 7.1 加载态

| 场景 | 方案 |
|------|------|
| 页面首次加载 | 骨架屏（矩形块 + 闪烁动画） |
| 按钮操作中 | `van-button` loading 属性 + disabled |
| 列表翻页 | 底部 `van-loading` + "加载中..." |
| 下拉刷新 | `van-pull-refresh` |
| 全页加载 | 页面居中 `van-loading` |

### 7.2 反馈

| 操作 | 反馈 |
|------|------|
| 加入购物车 | `van-toast` type="success" + "已加入购物车" |
| 下单成功 | 跳转订单详情 |
| 取消订单/预约 | `van-dialog` 二次确认 → `van-toast` "已取消" |
| 手机号绑定 | `van-toast` "绑定成功，已同步 N 笔历史订单" |
| 门店绑定 | `van-toast` "绑定成功" → 返回上一页 |
| 网络错误 | `van-toast` type="fail" + "网络异常" |
| 参数错误 | `van-toast` + 错误消息 |
| 权限不足 | 绑定手机号 overlay |

### 7.3 空状态文案

| 场景 | 文案 |
|------|------|
| 订单列表 | "暂无订单" |
| 预约列表 | "暂无预约记录" |
| 疗程卡 | "暂无可用疗程卡" |
| 家居产品 | "暂无家居产品" |
| 购物车 | "购物车是空的" |
| 商品列表 | "该分类暂无商品" |
| 搜索无结果 | "未找到相关商品" |
| 优惠券 | "暂无优惠券" |

### 7.4 防连点策略

所有涉及后端请求的按钮操作：
1. 点击后立即 `setData({ submitting: true })`
2. 按钮显示 `loading` + `disabled`
3. 请求完成后恢复

## 8. 约束保障（前端视角）

| real.md 约束 | 前端实现 |
|-------------|---------|
| 次数防超卖 | 前端不扣次数，仅通过 `service.detail` 查看 |
| 价格快照不可变 | `order.create` 时后端快照，前端显示的价格与下单独立 |
| 支付幂等 | 按钮防连点 + loading 态 + 后端幂等保障 |
| 状态单向推进 | 仅暴露"取消订单"（待支付→已关闭）、"取消预约"操作 |
| 待支付订单唯一 | 按钮防连点；后端 pre-check + 数据库约束 |
| 组织域数据隔离 | 所有查询 `WHERE client_user_id = ctx.auth.userId` |

# arch/016 转换单退款在本单闭环与转换时积分责任交接

## 背景与动机

#548 允许转换单转入商品逐项退款。旧项目折抵800元、补款200元得到未使用的1000元商品，可以退1000元。用户进一步确定所有退款冲抵留在转换单，不能追溯修改旧订单；旧单业绩和提成保留，只冲本单新增。

## 技术选型

| 方案 | 退款依赖 | 决策 |
|---|---|---|
| 退款后按来源回算原销售链 | 原单及多代来源 | 不符合本单边界，移除 |
| 转换时交接积分责任、退款时结本单 | 本单冻结快照和交接事实 | 采用 |

折抵不形成新增现金或新增提成。积分交接也不伪造赠送/冲销流水，不改变顾客余额。

## 数据模型

`conversion_point_transfers` 保存当前转换单的交接事实：顾客、来源订单/明细、目标转换单、永久移出的计分基数、实际已发积分责任、批次交接事实。目标单+来源明细唯一，金额和积分非负。来源ID保留审计用途；退款不查询来源订单或来源商品。

复用 `sale_items.conversion_value_snapshot` 的版本2：冻结已付本金与责任份额，区分转入旧积分责任和本单真实补款基数，保存已退及再次转出份额、现金流水标记。快照和内部退款责任均不进入公共DTO。

## 架构设计

转换的持锁事务内永久移出来源计分资格，将实际已发积分批次的归属转到当前转换单。旧批次保留赚取、到期、过期状态及实际剩余量；拆批次只拆责任和余额，不重新发放365天积分。已使用或已过期积分不复活。没有发过的旧积分不因折抵补造。

本单补款独立累计赠点。积分目标为本单尚未退/转出的旧积分责任，加本单剩余补款基数按100元1分向下取整；已发责任为本单积分流水净额+本单移入责任−本单移出责任。重复结算差值为零。来源单以后仅扣自己的永久移出基数，不读取转换退款。

退款使用本单快照按毛退本金减少责任，手续费不保留已退权益或积分。本单负积分流水只消耗本单批次，不用其它订单批次填补已用/已过期责任。会员消费仍按真实全量消费汇总，退款负额归本单门店和期间；这不是追溯回写旧消费。

角色分配只反冲本单已有正向余量。例如旧员工80元提成保持原账，补款新增员工20元最多冲20元。服务、提货、用券和赠券仅处理本单已有绑定。旧商品、次数、数量、旧欠款不恢复。

关闭未付款转换属于撤销，恢复原权益与积分交接；逐商品退款不走撤销。积分开关和SAVEPOINT失败隔离保留，失败日志的目标也是本单。

历史责任无法确认时拒绝该项退款。只读审计给出缺口；有凭据的历史数据须经独立修复映射、私有库重放和评审后补建，退款运行时不猜算。

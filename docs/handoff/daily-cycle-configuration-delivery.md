## 使用方法

1. 系统管理 → 日报经营配置 → 经营周期。选择顶部模式页签，或新增模式。
2. 选择自然月（1日至月末）或跨月（26日至次月25日），按实际情况调整月日期、周日期。可增减周数，范围1～31周；必须连续覆盖整月。长期规则须在普通年、闰年和跨年均有效；31个单日周可用于有31天的单月例外，不能作为全年通用规则。
3. 勾选数据库中的真实市场。一个市场只能属于一套专用模式；未分配市场自动沿用总部默认。重新勾选会移出原模式，保存时原子更新所有编辑中的模式及分配。
4. 填写生效日期。旧配置显示“长期生效”；新模式默认今天。只有经营月首日达到生效日期时，新生成月份才使用新版。旧规则版本保留，已生成月份不会因保存模式而改变。
5. 如某月有例外，展开“按月配置”，选择归属月，单独调整该月起止和周数；不影响其他月份。
6. 保存模式后，选择预览起止归属月（最多连续36个月），点击“预览 / 校验”，再“生成经营日历”。编辑规则预览与实际市场安排分开显示；实际安排遵守生效版本，并保留已有日期。
7. 若要调整已生成的未来月份，明确勾选“同时更新未开始且无日报、目标、PK关联的已有月份”，重新预览。只要批次中有已开始/有业务关联/不连续/重叠的月份，整批拒绝，不写入部分结果。
8. 删除模式、恢复默认均先进入未保存状态，需保存才生效。历史月份、目标、PK、日报快照保留。PK班级继续按实际经营月份单独配置，不自动沿用或复制。

归属月示例：2026-11的跨月周期为2026-10-26至2026-11-25。日号超过短月天数时取月末；周规则仍须覆盖实际月日期。跨月改自然月时，已有月份边界可能不连续，此时需要用单月例外衔接，不能覆盖正在使用的月份。

## 后端与跨端

- 模式和版本历史保存在现有system_configs；不新增表。
- 经营月继续保存实际日期和周数组，日报、进度、PK读取实际周期。
- 小程序、管理后台、云函数都按实际周数处理目标：前面各周手工填写，最后一周取月目标余额；只有一周时整月目标即该周目标。五项指标均保留“未设置”和“零值”的区别。
- 旧四周月份和关联ID保留；安全更新时周数相同保留原周ID，周数变化仅允许无业务的未来月份。

- 启用版本历史后，旧模板写入入口明确拒绝并提示使用周期模式，避免保存成功却不生效。

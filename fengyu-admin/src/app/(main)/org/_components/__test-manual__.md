# 组织架构节点移动功能测试清单

## 功能说明
新增功能：编辑节点时可以修改其上级节点

## 前端变更
1. 编辑对话框中"上级节点"从只读显示改为可选择的 Select
2. 下拉选项自动排除：
   - 自己
   - 所有子孙节点（防止循环引用）
3. 根据节点类型过滤合法的父节点：
   - 市场：只能选择总部
   - 门店：只能选择市场
   - 部门：可以选择总部/市场/门店，但不能选择部门
4. 只有当 parentId 真正改变时才传递给后端

## 后端变更
1. `updateOrgNode` 增加 parentId 变更校验：
   - 防止循环引用（不能移到自己的子孙节点下）
   - 类型层级约束验证
   - scope 权限验证

## 手工测试步骤

### 测试 1：正常移动门店节点
1. 登录管理后台
2. 进入"组织架构"页面
3. 选择一个门店节点（如"九江丽都店"）
4. 点击"编辑"
5. 在"上级节点"下拉框中应该只看到市场类型的节点
6. 选择一个不同的市场节点（如"九江风尚"）
7. 点击"保存"
8. 验证：节点成功移动，左侧树结构更新

### 测试 2：防止循环引用
1. 选择一个有子节点的节点（如"九江风尚"市场）
2. 点击"编辑"
3. 验证："上级节点"下拉框中不应该出现：
   - 自己（"九江风尚"）
   - 所有下级门店（"九江梦时代店"等）
4. 验证下拉框中只有符合类型约束的节点

### 测试 3：类型约束验证
1. 编辑一个市场节点
2. 验证：只能选择"总部"作为上级节点
3. 编辑一个部门节点
4. 验证：可以选择市场或门店，但不能选择其他部门

### 测试 4：创建模式不受影响
1. 点击"新增子节点"
2. 验证："上级节点"显示为只读，无法更改（保持原有行为）

## 预期结果
- ✅ 编辑时可以修改上级节点
- ✅ 防止循环引用
- ✅ 遵守类型层级约束
- ✅ 创建模式保持不变
- ✅ 无权限时显示错误提示

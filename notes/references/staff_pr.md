# 员工端（B端）产品需求

> 角色：店长（门店经理）/ 美容师 | 端口：员工端小程序
> **术语备注**：本文档中的「院装产品」对应 PG `product_type` enum 的 `'家居产品'`（2026-04-25 重命名）。文档为历史规范快照，未逐行替换。

---

## 核心链路（员工端视角）

### 场景 A：客户端下单后员工端联动

| 步骤 | 操作 |
|------|------|
| 1 | 收到顾客线下付款申请，执行"确认线下收款" |
| 2 | 进入顾客档案 → 日历视图 |
| 3 | 日历上实时出现标记：该顾客当日消费金额 |

### 场景 B：员工端开单（扫码收款）

| 步骤 | 操作 |
|------|------|
| 1 | 选择顾客，添加服务项目，完成营业额分配 |
| 2 | 系统生成订单二维码，展示在屏幕上 |
| 3 | 若客户选择线下付款则确认收款；若微信支付则自动到账 |
| 4 | 进入顾客档案 → 日历视图，日历实时出现消费标记 |

### 场景 C：服务单提交与完成

**分支一：有预约**

| 步骤 | 操作 |
|------|------|
| 1 | 收到顾客预约通知，进入预约管理，点击「确认预约」 |
| 2 | 顾客到店，点击「顾客已到店」，记录到店时间（预约状态不变） |
| 3 | 提交服务单，系统自动关联该预约记录（`appointment_id`） |
| 4 | 点击「开始服务」，服务单状态进入`服务中` |
| 5 | 服务完成后点击「确认完成」，系统扣减 1 次疗程次数，服务单进入`已完成` |

**分支二A：散客，已有订单（无预约，直接到店）**

| 步骤 | 操作 |
|------|------|
| 1 | 顾客到店，员工在顾客档案中找到对应已支付订单，选择订单行 |
| 2 | 提交服务单，关联该订单（`order_no`），`appointment_id` 留空 |
| 3 | 点击「开始服务」，服务单进入`服务中` |
| 4 | 服务完成后点击「确认完成」，系统扣减 1 次，服务单进入`已完成` |

**分支二B：首次到店体验，无任何订单**

| 步骤 | 操作 |
|------|------|
| 1 | 顾客到店，员工选择顾客，点击「创建体验单」（`order_type = 体验`，店长自定义金额） |
| 2 | 完成支付确认（流程与正式订单相同：微信支付或线下确认收款） |
| 3 | 从体验单中选择项目行，提交服务单 |
| 4 | 后续同分支二A |

## 功能模块

### 3.1 开单（核心功能）

- **权限**：仅店长（门店经理）可开单
- **开单流程**：
  ```
  选择顾客 → 选择开单模式（商品目录/促销方案/体验单）→ 添加项目 → 营业额分配 → 生成订单二维码 → 客户扫码确认付款
  ```
- 开单后生成二维码，客户扫码后在客户端小程序完成支付
- **顾客手机号为必填项**：选择顾客时必须填写或确认手机号，系统自动查询该手机号是否已注册客户端小程序；已注册则直接关联 `client_user_id`，订单立即在顾客端可见；未注册则以手机号作为临时标识，待顾客绑定手机号后自动关联
- 开单时订单即写入数据库（状态`待支付`），客户扫码后加载同一笔订单进行付款，不重复创建
- 客户可选择微信支付或线下付款
- 线下付款订单需由店长执行"确认收款"后才进入`已支付`
- 开单页展示二维码状态：待扫码 / 已扫码待付款 / 已付款
- 门店未配置店长时，前端直接提示"请先配置门店店长"，不开放"授权员工开单"

> **营业额分配可编辑窗口**：开单后、顾客扫码前（二维码状态为"待扫码"时），店长可重新进入营业额分配界面修改分配方案。顾客扫码后（二维码状态变为"已扫码待付款"或之后），分配方案立即锁定，不可再修改。如需修改，须作废当前订单（置为 `已关闭`），重新开单并完成分配。

> **数据来源（顾客选择）**
> - 顾客搜索：WorkFine `UDT_S_311`（顾客档案，只读）
> - 顾客身份关联：PG `client_wechat_users`（通过手机号匹配）
> - 员工开单人：WorkFine `UDT_S_287`（人事档案，只读）

#### 体验单开单

仅店长可创建体验单，用于首次体验/引流场景：

```
选择顾客 → 选"体验单"类型 → 添加体验项目（从商品库选择）→ 店长自定义金额 → 完成营业额分配 → 生成订单二维码或线下确认收款 → 支付完成后从该订单创建护理单
```

- 体验单（`order_type = 体验`）走与正式订单相同的支付流程，支持微信支付或线下确认收款
- 支付确认后，再从该体验单中选择项目行创建护理单

#### 促销方案开单

仅店长可创建促销方案订单，用于套餐销售场景：

选择顾客 → 选择促销方案 → 查看方案项目（不可增删）→ 营业额分配 → 生成二维码或线下收款

- 促销方案订单（`order_type = 促销方案`）只能单独成单，不可与其他商品混合
- 方案内项目价格来自 WorkFine UDT_M_1460（促销售价），赠品价格为 0
- 走与正式订单相同的支付流程
- MVP 仅支持一次性全额付款

#### 项目选择（SPU/SKU）

添加项目时复用与客户端相同的三层商品结构：

1. **左侧品项分类选择器**：品项分类节点（来自 UDT_M_229，21 种可用）；院装产品作为固定末尾节点
2. **右侧 SPU 列表**：展示该分类下的商品卡（名称、价格起步、生美/非生美标签），选定后加入订单行
3. **SKU 规格选择**：点击商品后弹出规格面板，显示全部 SKU（规格名 + 价格）
4. **订单行**：每个 SKU 对应一行，记录 `workfine_item_id`（疗程项目编号或商品编号）、名称、规格、价格、数量

- 同一 SPU 可多次添加不同 SKU（如同时购买 10 次卡和 20 次卡）
- 院装产品 SKU 对应 `UDT_M_341.UDF_M_1870`（商品编号），疗程卡/单品 SKU 对应 `UDT_M_1281/1383.UDF_M_14503`（疗程项目编号）
- SKU 价格从 WorkFine 实时读取，开单时快照存入订单行

> **数据来源（项目选择）**
> - 品项分类列表：PG `product_spu`（category 去重派生，不直接查 WorkFine UDT_M_229）
> - SPU 列表：PG `product_spu` + `product_spu_sku_map`（is_active 过滤）
> - SKU 价格/疗程次数：运行时从 WorkFine 实时读取（疗程卡/单品 → `UDT_M_1281`/`UDT_M_1383`；院装产品 → `UDT_M_341`）
> - 订单写入：PG `orders` + `order_items`

#### 促销方案项目

选择促销方案时，方案内所有项目自动填入订单，不可单独增删：

1. **方案列表**：从 WorkFine UDT_S_1459 读取有效方案
2. **方案详情**：展示方案内所有项目（UDT_M_1460），含项目名称、促销售价、原价、是否赠送
3. **价格来源**：UDT_M_1460.UDF_M_17171（促销售价），赠品（UDF_M_17174='是'）价格为 0
4. **SKU 解析**：通过 UDF_M_17163 关联 product_spu_sku_map

> **数据来源（促销方案）**
> - 方案列表：WorkFine `UDT_S_1459`（只读）
> - 方案项目：WorkFine `UDT_M_1460`（只读）
> - 促销售价：`UDT_M_1460.UDF_M_17171`
> - SKU 解析：`UDT_M_1460.UDF_M_17163` → PG `product_spu_sku_map`

> **MVP 简化**：优惠金额、是否赠送功能暂为默认值（开关在 Web 端控制）。

### 3.2 营业额分配（核心功能）

开单完成后，店长进行营业额分配：

#### 基本规则

- 先选择部门，再选择该部门下可分配业绩的员工
- 可分配业绩的员工由"是否可分配业绩"字段控制

#### 同部门分配

- 多名美容师参与时，分配总额 ≤ 实收金额
- 可选分配比例：3:7、4:6、5:5、2:8 等

#### 跨部门分配

- 美容部为基础服务部门
- 跨部门时各部门可各按实收金额分配（总额可达实收 2 倍）
- 示例：推广部引流 + 美容部服务 → 各分配 10000 元

#### 默认跳出人员

- 默认顾客下单时指定的美容师（对应订单 `preferred_employee_id`）
- 可选当前门店的所有美容师

#### 客户端未指定美容师的订单

- 顾客端自助下单时若未指定美容师（`preferred_employee_id` 为 null），订单支付后营业额分配入口同样出现在"订单详情"页
- 分配界面无默认候选人，店长从当前门店全体可分配业绩员工中手动选择
- 分配规则与其他订单相同（同部门总额 ≤ 实收；跨部门各按实收）

#### 说明

- 营业额分配属于订单级操作，不在服务单上进行
- 客户端自助下单时已指定美容师，支付成功时系统自动创建分配记录，店长可在订单详情页查看，无需手动操作；未指定美容师则不创建分配记录
- 员工端开单时，店长在开单流程中手动完成营业额分配
- 体验单（`order_type = 体验`）支付确认后同样需要进行营业额分配，流程与正式订单相同；体验单金额由店长自定义，分配以实际到账金额为准
- 营业额分配可修改窗口：开单后顾客扫码前（二维码状态"待扫码"）可修改分配方案；顾客扫码后分配方案立即锁定，如需修改须作废订单重新开单

> **数据来源**
> - 部门列表：WorkFine `UDT_S_287.UDF_S_1513`（职能部门，只读）
> - 可分配员工：WorkFine `UDT_S_287`（按门店+部门筛选，只读）
> - 分配记录写入：PG `revenue_allocations` + `revenue_allocation_items`

### 3.3 顾客档案与日历视图

#### 顾客档案

- 展示顾客基本信息、消费记录、绑定门店

#### 日历视图

- 按日展示顾客消费记录
- 每日标记消费金额
- **实时更新**：顾客订单进入`已支付`后日历立即显示消费标记（5 秒内）
- 支持按月浏览
- 同一顾客同一天多笔订单按日汇总金额，可展开查看明细订单
- 入账口径：按`已支付时间`统计，`待支付/待确认收款/支付失败/已关闭`订单不得入账

> 这是会议演示的**核心亮点**，需确保下单→日历标记的实时性和视觉效果。

> **数据来源**
> - 顾客基本信息：WorkFine `UDT_S_311`（只读）
> - 日历消费数据：PG `orders`（WHERE status = '已支付'，按 paid_at 聚合）

### 3.4 预约管理

#### 预约到服务完成流程

```
预约确认 → 顾客到店 → 提交服务单（关联预约） → 开始服务 → 确认服务完成
```

| 步骤 | 操作 | 状态变更 |
|------|------|---------|
| 1 | 查看待确认预约，点击「确认预约」 | 预约状态：待确认 → 已确认 |
| 2 | 顾客到店，点击「顾客已到店」（记录到店时间，不改预约状态） | — |
| 3 | 提交服务单，系统自动关联该预约记录 | 服务单创建，状态：待服务 |
| 4 | 点击「开始服务」 | 服务单状态：待服务 → 服务中 |
| 5 | 服务完成后点击「确认完成」 | 服务单状态：服务中 → 已完成，扣减 1 次疗程次数；若扣次后该订单行剩余次数归零，系统自动将该订单行所有处于 待确认 或 已确认 状态的预约置为 已关闭 |

#### 服务单与预约的关联关系

- 提交服务单时，`appointment_id` 为**可选**：
  - 有预约：选择关联的预约记录，一条预约对应一张服务单，不可重复创建
  - 无预约（散客直接到店）：`appointment_id` 留空，直接提交服务单
- 无论有无预约，提交服务单时**必须**关联一个订单（`order_no` 必填）；如顾客无已支付订单，需先创建体验单
- 服务单关联预约后，预约详情页可直接跳转查看对应服务单

#### 权限

- 店长、被预约美容师均可推进服务状态
- 美容师仅可操作分配给自己的服务单

#### 消息提醒

- 顾客预约后，系统向对应美容师发送预约提醒
- 顾客到店签到后，系统通知美容师「顾客已到店，请准备服务」

> **数据来源**
> - 预约记录：PG `appointments`（读写）
> - 服务单：PG `service_orders` + `service_items`（读写）
> - 服务单核销关联：`service_items.item_flow_no` → PG `order_items.item_flow_no`
> - 美容师信息：WorkFine `UDT_S_287`（只读）

### 3.6 客户联系方式绑定

- 对于未绑定手机号码的客户，员工可协助完成手机号码的绑定操作
- 应用场景：顾客到店消费但未在客户端小程序绑定手机号时，员工可引导或协助绑定，便于后续服务跟进和订单关联
- 绑定后，该顾客的历史订单（通过手机号临时标识创建的）自动关联到其客户端账号

> **数据来源**
> - 手机号绑定：PG `client_wechat_users.phone`（读写）
> - 历史订单补全：PG `orders`（WHERE client_phone = 绑定手机号 AND client_user_id IS NULL）

## 状态机

### 订单状态机

```text
待支付 -> 已支付 -> 已完成
待支付 -> 支付失败
待支付 -> 已关闭
待支付 -> 待确认收款 -> 已支付
支付失败 -> 待支付（店长手动重置，允许顾客重新发起付款）
```

- `已支付`触发：微信支付回调成功，或店长确认线下收款成功
- `待确认收款`：仅用于顾客端选择线下付款后的中间状态

### 服务单状态机

```text
待服务 -> 服务中 -> 已完成
```

- 只有店长或被分配的服务人员可推进状态
- 仅在`服务中 -> 已完成`时扣减 session_used 次（疗程卡/单品均适用），且剩余次数不得小于 0
- 重复点击"完成服务"时，后端按同一服务单 ID 幂等处理，不得重复扣次

## MVP 验收标准（员工端相关）

1. 订单进入`已支付`后，顾客日历在 **5 秒内**出现当日消费标记
2. WebSocket 断开情况下，员工端在 **30 秒内**通过轮询看到同一笔消费
3. 同一笔订单在日历中仅计入一次（无论重复提交多少次）
4. 同一服务单重复点击"完成服务"不产生重复扣次
5. 美容师不可开单（角色越权操作应被拒绝）
6. 技师不可查看客户完整手机号
7. 开单后 PG 自托管数据库订单表中能查到同一笔记录
8. 完成营业额分配后 PG 自托管数据库营业额分配表中能查到分配明细

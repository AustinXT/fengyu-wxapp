**时间：** 2026年7月23日  
**参与方：** 夜航星（技术方）、张凯（业务方）、邵冬、刘大印、贺东群

## 一、进销存与家居产品库存

### 当前问题

原 WorkFine 中存在多张库存相关表单，业务希望在新系统中承接门店报货、入库、退货、调拨、顾客领取、报损等流程。家居产品与销售订单、SKU、库存之间需要形成闭环，尤其是顾客购买后领取商品时，不能出现购买 A 商品却领取 B 商品的情况。

### 讨论过程

张凯说明，门店报货从产品库中选择产品和数量；市场汇总门店报货后提交给供应链；供应链发货后，市场入库并给门店配货，门店再做入库。一次报货可能分批到货，因此一个报货单可能对应多个入库单。

夜航星确认，新系统中的库存表单与 WorkFine 不再直接关联，业务数据存放在新系统数据库中；如主管、市场、供应链层级还需要提取数据，可以从外部数据库读取，但这些表单不会再呈现在 WorkFine 中。

关于价格，张凯确认店长不需要在小程序查看价格；财务主要在电脑端使用系统。双方倾向于员工端小程序只展示产品和数量，不展示价格，也不在小程序内做细粒度价格权限；管理后台中市场财务/管理员可查看价格。

关于审批，张凯确认院退货单和院产品报损单需要市场层级财务审批，因为这两类单据涉及退回市场或总部确认报损，不能由门店单方完成。

关于单据留存，入库环节需要保留市场给门店的签字单。顾客领取可改为线上提货记录并关联订单；调拨、报损暂不需要纸质单据。门店之间调拨仅限同一市场内部。

### 结论与待办

| 事项 | 负责方 | 说明 |
|------|--------|------|
| 库存单据模块 | 夜航星 | 覆盖报货、入库、退货、调拨、顾客领取、报损等流程，具体 8 张表名称需再核对 |
| 顾客领取关联订单 | 夜航星 | 领取必须关联销售订单和 SKU，只能领取已购对应产品，并扣减库存 |
| 报货/入库一对多 | 夜航星 | 报货不影响库存，入库按实际到货分批处理并展示未入库数量 |
| 价格展示 | 夜航星 | 员工端不展示价格；管理后台按财务/管理员权限展示 |
| 审批 | 夜航星 | 院退货单、院产品报损单需要市场财务审批 |
| 实时库存 | 夜航星 | 员工端看本店库存；管理后台库存模块统一展示，后台可含价格 |
| 入库单据留存 | 待确认 | 需确认是否要求上传照片/附件，还是仅记录签收确认 |
| 导出功能 | 待确认 | 库存相关表单是否全部支持导出，会议中未定 |

## 二、积分系统与会员权益

### 当前问题

积分系统需要明确抵扣、发放、过期、兑换、会员权益自动发放等规则。业务文档中还包含积分加现金、积分抽奖、积分捐赠等较多扩展玩法，需要判断哪些进入当前迭代。

### 讨论过程

张凯提出，顾客消费后可用积分抵扣，但抵扣比例需要可调。日常场景下，10000 元订单最多抵 300 元，即 3%；活动期间可临时放宽到 5%。夜航星建议做成全局配置，由后台手动调整，活动结束后再改回。

积分抵扣和营业额分配关系上，夜航星原本倾向于积分不影响营业额分配基数，以避免分摊到明细造成小数点复杂度。张凯认为这会导致员工提成成本增加，因为顾客实际少付的钱仍被计算提成。讨论后，积分应像优惠券一样放在订单明细上方，作为同级抵扣项处理，并摊到商品明细上，影响实收和营业额分配基数。

积分抵扣上限按优惠券/积分使用前的订单金额计算，不按抵扣后的实付金额计算。积分发放则按实际支付金额计算，例如 10000 元订单抵扣 300 元后，按 9700 元发放积分。退款时需要扣回该订单产生的积分。

积分兑换专区方面，张凯说明兑换商品仍来源于 SKU，但希望由不同权限的人维护，因此不直接并入普通商品管理入口。兑换专区可以设置栏目分类和兑换所需积分。会议中确定当前先做纯积分兑换，不做“积分 + 现金”。复杂玩法如 1 积分抵 1.5/2 元、积分抽奖、积分捐赠、复杂风控等暂缓，张凯需回业务部重新确认。夜航星建议若目标是促进消费，优先考虑“积分发放翻倍”活动，而不是提高积分消耗价值。

会员权益配置方面，张凯提出自动发券缺少数量字段，导致升级礼、生日、感恩日等场景只能通过创建大额券或在名称上写数量规避。夜航星确认可在配置中增加数量字段；但订单使用券仍维持一次只能用一张，多张券使用会显著增加复杂度。

关于历史会员权益，夜航星说明现有逻辑已按历史订单推算会员成为日期，历史已成为会员的顾客不会重复发一次新会员权益；新会员由定时任务扫描补发。

### 结论与待办

| 事项 | 负责方 | 说明 |
|------|--------|------|
| 积分抵扣比例配置 | 夜航星 | 日常 3%，活动可调至 5%，作为后台全局配置 |
| 积分抵扣同级优惠券 | 夜航星 | 积分抵扣影响实收，并摊到明细影响营业额分配基数 |
| 积分发放基数 | 夜航星 | 按实际支付金额发放积分 |
| 退款扣积分 | 夜航星 | 退款时扣回该订单产生的积分 |
| 积分商城 | 夜航星 | 从 SKU 选品，设置兑换积分和分类；当前只做纯积分兑换 |
| 积分复杂玩法 | 张凯 | 积分加现金、抽奖、捐赠、1 积分抵多元等暂缓，回业务部确认 |
| 会员权益发券数量 | 夜航星 | 升级礼、生日、感恩日等配置增加数量字段 |
| 积分有效期 | 待确认 | 会议中出现 365 天和 360 天两个口径；提醒节点为 60/30/7 天 |
| 积分商城入口 | 待确认 | 倾向顾客端和员工端都要，但需确认优先级 |

## 三、指标与分析口径

### 当前问题

数据指标中存在多处口径不清：续存页普及率的持卡人数、新客漏斗不同渠道的新客定义、会员成交率分母、转卡抵卡是否算会员等。

### 讨论过程

续存页普及率中，夜航星询问“持卡会员数”应指购买过疗程卡的人，还是当前仍有剩余卡项的人。贺东群确认按当前仍有剩余卡项统计，消耗完不再计入；张凯也确认按剩余卡项口径执行。该口径与“购买过卡项人数”不同。

新客漏斗中，张凯说明不同渠道的新客定义存在差异。地推、美团、抖音等渠道通常需要有系统内订单记录才算新客；转店顾客是收购或转让店带来的顾客，在美丫丫没有新订单，也应作为新客。夜航星总结：除转店外，其他渠道基本需要下单才算新客；转店按登记来源即可计入。

老带新场景中，若新顾客未登记，只是直接划老顾客的卡，系统无法识别为新客。会议中倾向要求门店按流程给新顾客开赠送单、发券、销售单或服务单，必须留下系统记录。

会员成交率方面，夜航星指出如果某些顾客未到店但直接下单成为会员，会导致分子和分母口径不一致。张凯确认，漏斗中的会员成交率应基于“到店的人中有多少成为会员”，因此未到店会员应从该指标分子中剔除。若后续需要统计全部新客中的会员转化率，应作为另一个指标。

小美卡用户口径上，张凯解释为到店人群中未成为会员但已经有消费的人，用来区分“到店后仍未消费”和“到店后有小额消费但未转会员”的客户。

新会员首单金额与会员年度贡献值，均沿用前面漏斗里到店后转化的新会员口径。新会员首单金额取成为会员那一单，年度贡献值也仅统计这批新会员。

转卡抵卡成为会员的场景仍有分歧。现有系统按实付金额判断会员门槛，因此顾客先买 511，再抵卡购买 1990，第二单实付 1479 时，系统不会算成会员。张凯认为从顾客角度可能不合理；会议最后决定会后再确认业务口径。

### 结论与待办

| 事项 | 负责方 | 说明 |
|------|--------|------|
| 续存页普及率 | 夜航星 | 持卡会员数按当前仍有剩余卡项的人统计 |
| 新客渠道口径 | 夜航星 | 除转店外，原则上需有首单/服务记录才算新客 |
| 转店新客 | 夜航星 | 来源为转店的顾客可不要求新订单，按登记计入 |
| 老带新 | 业务方/门店 | 必须按流程登记新顾客并产生赠送单、券、销售单或服务单等记录 |
| 首次到店 | 夜航星 | 只统计第一次到店，后续复到不重复计入首次到店 |
| 会员成交率 | 夜航星 | 分母为到店人数，分子为到店人群中成为会员的人 |
| 小美卡用户 | 夜航星 | 到店但未成为会员、已有低于会员门槛消费的人 |
| 新会员首单金额 | 夜航星 | 取成为会员那一单的金额，口径与到店转会员人群一致 |
| 转卡抵卡是否算会员 | 张凯/业务方 | 当前系统按实付金额，不算；业务是否调整需会后确认 |
| 渗透率指标 | 刘大印/业务方 | 暂缓，等当前指标完成后再对接 |

# 2026-05-07 凤御技术沟通会议要点

## 核心决议

### 1. WorkFine 历史数据迁移（最终方案）

否决"订单从零开始"——会让会员等级/消费档位/顾客类型等标签算不出来，同比/环比也要等满一年。最终采纳"**全量抓取 + 未审核 + 顾客触发核对**"方案：

- **抓取字段最小化**：手机号、归属门店、金额、日期（不抓品项名、不抓次数，"抓得越多错得越多"）
- 上线前一把抓所有历史订单，状态默认"未审核"
- **单独页面**展示，不混入订单管理
- 顾客到店时：微信登录 → 提取手机号 → 员工核对该顾客的金额/日期 → 审核入库 → 标签重算
- 顾客管理页提供触发按钮，"来一个核一个"
- 关联键：WorkFine 顾客编号 ↔ 手机号 ↔ 小程序 openid；手机号错的可在管理后台修正

### 2. 剩余次数：寄存订单

复用 `sale_orders`，新增订单类型（与"内部单"同一区分字段），不计入统计但可生成服务单。不单独建表。

### 3. 品项映射

夜航星已用 AI 推断映射表，需张凯按规范填报"原品项 → 新品项"对照。

## 功能模块决议

| 模块 | 决议 |
|------|------|
| 会员权益触发类型 | 仅 3 种：升级、生日、感恩日 |
| 会员权益动作 | 仅 2 种：送优惠券、送积分（实物不支持） |
| 积分 | 不能无端赠送；消费积分/路费积分写死，不可配置 |
| 周年纪念日等 | 由门店手动赠券解决 |
| 库存管理 | 不重构 WorkFine 8 张表逻辑；小程序复制门店端录入界面，数据回写 WorkFine；市场/区域不进小程序 |
| 商品图 | 封面图 1 张（列表+顶部）；详情图多张（描述下方） |
| 顾客档案 | 不批量导入，到店注册时自然产生 |
| 商品/商城/提成矩阵/员工/门店 | 重新录入 |
| 权限 | 通过菜单显隐控制，已自动化测试覆盖；商学院无商品/员工管理 |
| 优惠券 | 仍有 bug（绑定限制条件未生效），暂不手动测试 |

## 关键判断（夜航星观点）

- 标签计算横跨上线前后，时间上具有连续性，**必须有历史订单**才能算准
- 截面数据填入到任何单一时间点都不合适，会偏
- 手填累计金额会被新订单触发的重算刷掉，行不通
- "不要搞那么多定制化功能，要规范要约束"

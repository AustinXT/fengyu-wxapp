## 四、数据看板

### 首页简单数据指标

张凯希望首页展示简单汇总数据，不涉及复杂计算：

| 指标 | 定义 | 说明 |
|------|------|------|
| 客流 | 服务单数量 | 一个顾客一天算一次，一个月可重复计算 |
| 客量 | 客户数量 | 一个人一个月只算一次（按日期+顾客编号去重） |
| 消耗项目 | 服务单中的划卡次数 | 对应服务单中的打卡记录 |
| 业绩 | 收款金额汇总 | 不限付款方式，"现金"二字可去掉 |
| 消耗金额 | 划卡对应的单价汇总 | 如：发一次 200，发两次 400 |
| 新会员 | 首次消费达到 1980 元 | 低于 1980 为普通流量顾客，不算会员 |

### 角色视角差异

| 角色 | 数据范围 |
|------|---------|
| 美容师 | 仅看自己服务的数据 |
| 店长 | 看本店所有数据（拿整店业绩，不与美容师分业绩，有股份） |
| 区域经理/总监 | 默认看负责区域所有数据，可筛选具体门店 |

首页需增加：
- **日期筛选**（已有）
- **范围筛选**（区域总监可选门店/区域）

### 看板与决策分析系统的分工

达成共识：
- **简单汇总数据**（客流、消耗、业绩等求和数据）→ 小程序首页展示
- **复杂分析计算**（如复购率等）→ 跳转到决策分析系统
- 小程序侧重**门店员工日常操作**，决策分析侧重**管理层数据决策**
- 需要列一个清单明确哪些指标在小程序展示、哪些跳转分析系统

### 提成数据展示

- 原来在"我的"页面中，入口较小
- 建议参考"客户预约"板块的方式**放大展示**

## 五、看板快捷按钮方案

### 需求

顾客分类筛选（如活跃顾客、即将流失顾客、沉睡顾客等）需要用**大按钮（快捷按钮）**展示，方便业务人员直观使用。

### 方案讨论与结论

| 问题 | 结论 |
|------|------|
| 按钮能否动态更换？ | 不能随意新增逻辑，但可从**预设的全部按钮中选择展示哪些** |
| 展示数量 | 默认展示前 6 个，可点击展开查看全部 |
| 布局 | 自适应，每行 3-4 个，多了自动换行 |
| 品项按钮 | 品项有 20-30 个，只展示常用的几个大类，其余可点击展开筛选 |
| 默认规则 | 可按销售占比超过 10% 自动设为默认快捷按钮 |

## 六、顾客管理

### 顾客分类与标签

顾客分类有多个维度：

- 会员等级：粉丝、铁粉、黑钻等
- 计算规则：根据**消费金额滚动计算**，类似银行会员积分
  - 本年度达到对应金额即升级
  - 满一年未继续消费则重新刷新等级
- 需要预留大量顾客标签位

### WorkFine 迁移

- **未来方向**：所有员工档案和顾客档案都迁移到小程序
- **原因**：WorkFine 只有前台和办公室人员能使用，普通员工无法登录
- 小程序端将成为主要操作平台

## 七、订单体系扩展

### 订单类型划分

开单流程确定为：

```
开单 → 选择订单大类（销售单/回款单/转换单）
       → 若选销售单 → 选择子类型（体验单/普通单/内部单）
           → 体验单：只能选体验卡（68元/99元等）
           → 普通单：可选家居产品、促销方案、护理项目
           → 内部单：员工或家属消费，自动半价
```

### 体验单（售前体验卡）

| 要素 | 说明 |
|------|------|
| 定义 | 推广部地推销售的便宜体验卡（68元、99元、100元等） |
| 顾客身份 | 购买体验卡的人是**潜在客户**，尚未成为会员 |
| 护理单 | 体验单也需创建护理单，影响美容师手工费 |
| 员工归属 | 体验单的员工为开单员工 |
| 业绩计入 | 体验卡收入**不计入业绩** |
| 顾客档案 | 小程序端不再区分"体验顾客档案"和"正式顾客档案"，统一管理，通过会员/非会员标识区分 |
| 标记 | 需打标记，后续分析数据时可剔除 |

### 内部单（员工消费）

| 要素 | 说明 |
|------|------|
| 适用对象 | 员工本人或员工家属 |
| 优惠方式 | 统一半价（手动填写优惠金额或自动给半价） |
| 审批流程 | 店长审批时线下确认是否为员工/家属 |
| 数据标记 | 必须打标记，分析时剔除（不算顾客数、不计入会员等级计算） |

## 八、优惠券体系 ✅

### 券种分类

讨论后将优惠券抽象为统一模型：

| 券种 | 本质 | 说明 |
|------|------|------|
| 现金券 | 直接抵扣金额 | 提取后直接抵钱 |
| 项目券 | 限定范围的现金券 | 限定在特定项目中使用，本质也是现金抵扣 |
| 折扣券 | 乘法计算 | 逻辑最复杂 |

通用设计要素：满减条件、适用范围、适用门店。

方案：先出一版通用设计，让销售人员使用后再根据反馈调整。

## 九、提成计算

### 美容部提成

- 按照已有的提成系数表计算
- 基于服务单（划卡）关联到具体美容师

### 推广部提成

推广部提成分两部分：

| 类型 | 计算方式 |
|------|---------|
| 销售提成 | 阶梯提成（已有方案） |
| 卡金 | 按体验卡固定金额发放（如 68 元卡发 40 元卡金） |

- 卡金也有阶梯：30 张 800 元、40 张 1000 元、50 张 1200 元
- 建议将固定卡金转换为比例，统一处理方式
- 推广部提成规则需**单独出文字稿确定**
- 体验单的引入刚好解决了推广部卡数统计的问题

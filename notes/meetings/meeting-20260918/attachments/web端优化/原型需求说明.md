# WEB 管理端原型需求说明（经营数据板块）

> 配套原型文件：`WEB管理端-经营数据原型.html`（用浏览器打开即可操作，内部为演示假数据）
> 面向人群：连锁美容院运营 / 店长管理层；对接方：开发人员

---

## 一、背景与目标

小程序端受平台限制较多（报表展示、跨门店汇总、导出等能力受限），因此需要 WEB 管理端补齐。
本需求说明与原型图主要描述 **经营数据** 这一个板块的页面样式、字段与规则，供开发按图实现。

---

| 员工收入 | 提成配置表 | ⬜ **现有真实系统已有**（原型不做该配置页，只按它的提成点口径取数） |
| 首页工作台 / 顾客管理 / 卡项与产品 / 员工管理 / 系统设置 / 品项分类配置 | — | ⬜ 示意（灰态待规划，原型中不实现） |

> **原型注解已全部移除（按“当正式系统看”处理）**
> 页面上**不再有任何灰色说明文字**：① 各页底部的「口径说明」（`axis-note`）；② 筛选分组下的 `frow-hint`；③ 页头副标题（`page-head .sub`）；④ 全局筛选条与权限横幅里的说明句（`filter-hint` / `.exp`）；⑤ 表格页脚里的口径例句（只保留"共 N …"这类**数据**与分页）；⑥ 纯口径小标签（如"提成点取自提成配置表"）；⑦ 弹窗内与鱼骨画布脚注的操作指引；⑧ 文案里的"示例 / 样例 / 演示"字样。
> **保留的是"数据性信息"**：KPI 卡与其小字、信息条（模式 / 归属月 / 范围 / 视图 / 条数 / 合计等标签）、表格计数与分页、图例、单位、状态标签。
> 因此**口径与规则一律以本需求说明为准**，不再在界面上重复解释。

> **信息架构约定（分析页怎么放 · 重点）**
> 1. **分析页只做一份**：挂在 `经营数据 → 分析 → 经营分析（趋势）`，**不为每张明细表各建一个分析页**（否则"N 张报表 × 各自分析页"会页面爆炸、口径还会分裂成 N 套）。
> 2. **"分析哪张报表"由页内的「🧭 数据来源」页签承担**，切来源只换指标字典 + 取数口径，**页面不换、门店与期间上下文不丢**。
> 3. **每张明细表都有就地入口**（表格右上「📈 看趋势」、频率表 4 张指标卡可直接点），带**来源 + 指标**上下文进入；**面包屑变三级** `经营数据 / 来源明细页 / 经营分析`，中间一级可点返回 —— 这样既"只维护一份"，又"一眼知道这条分析对应哪张明细表"。
> 4. **再加分析对象不新增页面**：将来给「员工管理 / 卡项与产品 / 顾客管理」做分析，只是多一个「数据来源」页签（补一份指标字典 + 取数口径）；若将来跨板块分析变多，可把这一页提升为一级「分析中心」，**页内结构不变、升级不返工**。

## 三、整体布局

1. **左侧**：一级/二级/三级导航。当前可点：`经营数据`（**明细**：日常数据一览表、顾客频率表、顾客剩余卡项清单、经营数据主表 ｜ **分析**：经营分析（趋势）｜ **目标进度**：美容师/门店/区域目标进度表、目标填报 ｜ **配置**：经营周期配置）、`员工收入`（员工提成日报、提成明细（下钻））与 `鱼骨图`（填报记录列表、填报画布）；其余灰态。
   - 「分析」分组下**只有一个入口**（经营分析），其下不再挂"××表趋势"之类的子页；分析对象在页面内部用「🧭 数据来源」切换（见 5.7）。
2. **顶栏右侧**：登录人信息。原型中提供「身份模拟」下拉（总部运营总监 / 南昌市场运营总监 / 店长 / 美容师），用于演示不同权限角色看到的效果，正式版本应去掉该下拉。
3. **内容区上方 = 全局筛选条**：
   - 筛选门店（下拉）
   - 开始日期（date）
   - 结束日期（date）
   - 按钮：查询 / 重置 / 导出 Excel
   - 筛选结果联动当前二级页面的全部表格与指标卡。

## 四、数据权限规则（重点）

| 角色（示例） | 进入二级页后的默认门店 | 可筛选范围 |
|---|---|---|
| 总部运营总监（全国市场） | 全国 · 全部门店 | 全国所有市场/门店 |
| 南昌市场运营总监 | 南昌市场 · 全部门店 | 仅南昌市场门店 |
| 南昌·红谷滩店店长 | 本店（锁定，下拉禁用） | 仅本店 |
| 南昌·红谷滩店美容师（示例） | 本店（锁定，下拉禁用） | 仅本店 · 且仅在「目标填报」页填报**本人**目标 |

**实现约定**：登录接口返回该账号的权限范围（全国 / 某市场 / 某门店），
二级页面默认加载权限范围内的数据，门店下拉的可选项也只能是权限范围内门店，禁止越权。
**多选门店**：门店筛选为多选控件，默认“权限范围全选”；也可只勾 1~N 家查看单店/多店。
这样可覆盖“区域内还有片区/小区域经理只管 2~5 家门店”的情况，而无需为小区域增加一层权限架构（仍以账号返回的可选门店集合为准）。

## 五、页面一：日常数据一览表

同一统计周期，提供三个视角的汇总表（点击页签切换）：**① 经营类型汇总 / ② 具体品项汇总 / ③ 二级品项汇总**。

### 5.1 视角①：经营类型汇总

**注意：表头为单行结构（不做分组合并表头），避免“标题与数据错位”。**

| 字段（按从左到右顺序） | 说明 |
|---|---|
| 门店 | 门店名称（跨市场查看时可显示所属市场） |
| 自销自耗业绩 | 金额（元） |
| 他销他耗业绩 | 金额（元） |
| 他销自耗业绩 | 金额（元） |
| 生态合作业绩 | 金额（元） |
| 业绩合计 | = 上面 4 类之和 |
| 自销自耗服务 | 金额（元），浅绿列（服务类） |
| 他销他耗服务 | 金额（元），浅绿列（服务类） |
| 他销自耗服务 | 金额（元），浅绿列（服务类） |
| 生态合作服务 | 金额（元），浅绿列（服务类） |
| 服务合计 | = 上面 4 类之和（浅绿列） |

口径说明：
- **业绩板块 4 类**：自销自耗业绩 / 他销他耗业绩 / 他销自耗业绩 / 生态合作业绩（＝原来的 3 类再细分，**合计口径不变**）；
- **服务板块 4 类**：自销自耗服务 / 他销他耗服务 / 他销自耗服务 / 生态合作服务；
- 服务 = 服务类业绩，数值与业绩一样是**金额（元）**，不是次数；
- 表尾包含「合计行」= 当前筛选范围所有门店之和；**4 类之和必须等于对应合计**（可用于核对）。

### 5.2 视角②：具体品项汇总

| 字段 | 说明 |
|---|---|
| 门店 | 门店名称 |
| 安吉丽业绩 / 美在东方业绩 / 功能养生业绩 / 功能灸业绩 / 家居产品业绩 / … | 金额（元） |
| 品项业绩合计 | 本行各品项之和 |

**注意**：品项列来源于小程序端已有的【品项分类】数据，原型不制作该配置页；
示例表格第 6 列「其他品项业绩」为占位，正式开发时该列应随品项配置**动态生成/增删**。
原型保证：视角②的品项业绩合计 = 视角①的业绩合计（口径勾稽一致）。

### 5.2.1 视角③：二级品项汇总（新增）

一级品项**打组**，组内是它下面的**二级品项**（表头为两行：上行＝一级品项，下行＝二级品项）。

| 元素 | 说明 |
|---|---|
| 行 | 门店 + 表尾合计行（与其它视角一致） |
| 列 | 每个一级品项下再拆二级品项（如「安吉丽」下拆「安吉丽·面部护理 / 安吉丽·身体养生 / 安吉丽·家居产品」）；最后 1 列＝**品项业绩合计** |
| 表头 | **两行分组表头**：第 1 行＝一级品项（跨该组的全部二级列，组左侧带分隔线），第 2 行＝二级品项；「门店」「品项业绩合计」两列 rowspan=2 |
| 勾稽 | **∑二级 = 所属一级**；**∑一级 = 品项业绩合计 = 视角①的业绩合计**（三层口径一致，便于核对） |
| 数据来源 | 同视角②：列随小程序【品项分类】的**一级 / 二级**配置动态生成 / 增删（原型不制作该配置页） |

### 5.3 页面：经营数据主表（经营数据 · 新增二级页）

- 依据：`经营数据主表.xlsx` → 工作表「凤御·经营」（字段与批注口径以该模板为准）。
- 字段（B~Y 列）：市场 / 门店 / 美容师人数；保有会员（前3月回店1次人头数）；回店1次当月人头·达成率；回店≥2次当月人头·达成率；被经营顾客（年度目标、年度消费人数、当月消费人数、被经营率·年度标准60%）；销售业绩（年度销售业绩目标、当月业绩目标、当月完成、当月完成率、年度累计达成）；客流及客耗（当月客流、当月售前/售后客流、当月项目数、当月总实耗、当月生美实耗、单次生美客耗）。
- 表头为两行：上方为各组“大标题 + 口径说明”（保有会员·售前不算/被经营顾客目标·季度拆分/销售业绩目标/客流及客耗，文字与 Excel 模板一致，按组着色），下方为明细字段列。
- 展示：达成率 / 被经营率按百分比；金额 / 实耗按元（部分目标字段模板可能为万元口径，以字段说明为准）；首两列（市场/门店）冻结、横向滚动查看；含合计行（模板“自贡·合计”）。
- 筛选/按钮：沿用全局门店与日期区间筛选、查询/重置/导出，与其它经营数据页一致。
- **实现注意（易错点）**：① 前端字段键必须**唯一**——「市场 / 门店」与「被经营率 / 当月客流」不能共用同一个键（对象字面量同名键会被后写的值覆盖，导致市场/门店列被数字顶掉）；② 「市场 / 门店」是**文本列**，不能走数字格式化（否则显示 `NaN`）；被经营率走百分比、当月客流走整数。
- 该页字段也是「经营分析」的**数据来源之一**（见 5.7.1）：分析页按本模板自带门店集取数，量值类字段可看趋势，比值类不参与趋势。

### 5.4 页面：目标进度表（经营数据 · 新增，含 3 个子页 × 2 个视角）

子页：
1. **美容师目标进度表**：区域 / 门店 / 美容师；
2. **门店目标进度表**：区域 / 门店；
3. **区域目标进度表**：区域（按市场汇总）。

每个子页有两个视角（页签切换）：

| 视角 | 字段 |
|---|---|
| 📅 周成果表 | 区域、门店、（美容师）、本周目标、本周达成、达成率、达成状态；**右侧再列本周 7 天的每日达成金额**（周一到周日） |
| 🗓 月成果表 | 区域、门店、（美容师）、本月目标、本月达成、达成率、达成状态；**右侧再列 第一周完成 / 第二周完成 / 第三周完成 / 第四周完成**（四周之和＝本月达成） |

规则：
- **达成状态**：达成 ≥ 目标 → 绿色 **✓ 达成**；否则红色 **✗ 未达成**；
- 达成率＝达成 ÷ 目标；金额单位为元；
- 周定义为**周一到周日**，日期列取「开始日期」所在周；月按自然月；
- 门店范围沿用权限范围与“门店多选”结果；区域表按所选门店所属市场汇总；
- 表尾含合计行；左侧列冻结、可横向滚动。
- **周期口径由「经营周期配置」决定**：月统计区间、月内每周的起止日、每周天数都可自定义（不固定 7 天）。
- **周期模式不给用户手选**：按「门店所属区域 → 经营周期配置里该模式的【适用区域】」**自动匹配**；模式与本期区间不单独放说明文字，而是显示在**页签右侧的「本期」信息**与页面下方的**口径信息条**里（筛选分组下方不再重复说明）。要改周期请到「经营周期配置」调整适用区域或起止日期。
- **「统计视角」升级为页面级页签**：`📅 周成果表` / `🗓 月成果表` 放在表格上方、做成**浏览器标签页样式**（选中＝白底 + 上圆角 + 顶部主色条，并“盖住”下方细线看起来与内容相连；未选中＝灰字透明底，悬停淡蓝底；整排坐在一条 1px 细线上），每个页签带一行小字说明“本周目标 · 每日达成” / “本月目标 · 各周完成”，页签右侧显示“归属月 / 周期区间 / 共几周 / 当前周”；
  切换页签只重渲染表格，下方筛选条与归属月的位置都不变。
- **归属月统一在全局筛选条**：与「筛选门店」同一行，仅 目标进度表 / 目标填报 显示（其它页面该位置显示“开始/结束日期、快捷区间”）；两页**共用同一个归属月**（选 2026-07 则填报与进度都按 2026-07 取数，避免两页口径不一致）。
- **筛选条按类型分两行**（不再挤在一行）：
  - 第 1 行「周期口径」（蓝色分组）：周次（仅在周成果表下出现）；
  - 第 2 行「视图与指标」（紫色分组）：视图（🧩 折叠块 / 📐 对齐矩阵）、指标；
  - 行内采用**固定列位的等宽网格（3 列）**：既铺满整行不留大片空白，又保证**某一项隐藏时其它项原地不动**——例如切「月成果表」隐藏「周次」后，「指标 / 全指标展示」不会挪位、归属月也不会跳到最右；
  - 筛选标题（统计视角 / 归属月 / 周次 / 指标 / 全指标展示）**加粗放大**（12.5px、700）比正文更显眼；
  - 每行的**说明文字另起一行放在该组筛选项下方**（而不是挤在右侧），例如“自动匹配到的周期模式”“为什么这两个展示项置灰”；
  - 选项不多的控件（下拉、单选按钮、指标页签）按分组带淡色底色，选中态用该组主色实心，避免清一色白框；
  - 操作按钮（按周自动分摊 / 保存填报）仍按惯例靠右，与页脚提示“点右上保存填报”一致。
- **「视图」在前、「指标」在后**（先决定“怎么看”，再决定“看谁”）：
  - 🧩 **折叠块**：一个指标一块 —— 指标＝`全指标` 时 5 块；指标＝某个单指标时 **1 块，块内保留该指标的「本周每日 / 各周完成」明细列 + 合计行**；

  - **两个方向都用“可点 + 自动纠正 + 说明”，不用禁用**（避免不懂系统的人卡在“为什么点不了”）：
    ① 对齐矩阵下点单个指标 → 自动切到「折叠块 + 该指标」，并提示原因；

- **筛选差异**：目标进度表、目标填报、经营周期配置页**不显示“开始/结束日期、快捷区间”**（周期由“所属区域自动匹配到的模式” + 归属月 + 周次 决定，日期重复）；这几页的“自动周次/自动归属月”以**今天**为基准。日常数据一览表 / 顾客频率表 / 经营数据主表 仍保留日期区间筛选。
- **重置按钮分页生效**：进度页重置“门店（回到权限范围）+ 归属月(自动) + 周次(自动)”；填报页重置“门店范围 + 自动归属月 + 门店目标维度”；配置页重置到默认模式页签；其他页仍重置门店+上月区间。

### 5.7 页面：经营分析（经营数据 → 分析 · 一个页面承接全部报表的走势）

> 定位：**明细页之外的"分析页"**——回答"近几个月 / 今年在涨还是跌、和去年比怎么样、哪家店拖后腿、目标完成得怎么样"。
> 结构：**一个分析引擎 + 4 个数据来源**（来源在页内切换）；明细页只提供入口，不各自建分析页。

#### 5.7.1 数据来源（页内「🧭 数据来源」页签 = 一份指标字典 + 一套取数口径）

| 数据来源 | 指标清单 | 取数口径 |
|---|---|---|
| 日常数据一览表 | 业绩合计、**自销自耗业绩、他销他耗业绩、他销自耗业绩、生态合作业绩**、服务合计、**自销自耗服务、他销他耗服务、他销自耗服务、生态合作服务**（10 项）＋ **各一级品项业绩（随小程序【品项分类】配置动态生成）** | 同 5.1 视角①/②/③（`makeDailyRow`），各视角与各层级可互相勾稽 |
| 顾客频率表 | 到店总人次、到店顾客数、消费合计、消耗合计、客单价（5 项） | 同第六节；**4 张带迷你趋势的指标卡可直接点进来看趋势** |

| 入口 | 行为 |
|---|---|
| 日常数据一览表 · 表格右上「📈 看趋势」 | 来源=一览表、指标=业绩合计 |
| 顾客频率表 · 表格右上「📈 看趋势」 | 来源=频率表、指标=到店总人次 |

进入后：**面包屑三级** `经营数据 / 来源明细页 / 经营分析`（中间一级可点回原页）；页内切换「数据来源」不丢 门店 / 期间 / 图形，指标自动回到该来源的首个指标，面包屑的来源名同步更新。

**筛选条件（沿用分组筛选条样式：第 1 行「分析对象」、第 2 行「指标与维度」，各自 3 列）**

| 分组 | 控件 | 说明 |
|---|---|---|
| 分析对象 | 🧭 数据来源 | 日常数据一览表 / 顾客频率表 / 经营数据主表 / 目标进度表（页签，标注每个来源的指标数） |
| 分析对象 | 📅 期间 | 近 6 个月 / 近 12 个月 / 今年以来（**按周时固定近 12 个自然周，该下拉禁用**） |
| 分析对象 | 🗓 时间粒度 | 按月（近 6 / 12 个月）｜按周（近 12 个自然周，周一~周日）；**目标进度来源为月度口径，点「按周」会自动回到「按月」并提示原因**（与"对齐矩阵下点单指标"同一套"可点 + 自动纠正 + 说明"约定） |
| 指标与维度 | 🎯 指标 | 随「数据来源」变化（清单见 5.7.1） |
| 指标与维度 | 🧩 门店维度 | 汇总（一条走势）｜按门店分列（每家一条，**最多同时画 8 家**，超出在页签右侧提示用「筛选门店」缩小） |
| 指标与维度 | 📈 图形 | 折线 ｜ 柱状 |

**图表区**：内联 SVG 手绘（**零第三方库、零 CDN**，保持"单文件双击即开"）；每点/每柱带 `<title>` 悬停显示"门店 · 期次：数值"；上方有颜色图例；多期时容器内横向滚动。

**明细表（两种形态）**

| 维度 | 行 | 列 |
|---|---|---|
| 汇总 / 单店 | 期次（最新在上） | 期次、本期、**（目标进度来源）目标 + 达成率**、上期、**环比**、（按月时）**去年同期**、**同比**、累计（客单价为"累计均值"） |
| 按门店分列 | 门店 | 门店、各期次、合计（客单价为"期间均值"）、环比（最新两期） |

**口径**：随「数据来源」变化（各来源口径见 5.7.1 与对应明细页章节）——例如顾客频率表来源：到店总人次＝所选范围内顾客到店次数之和；到店顾客数＝当期至少到店 1 次的人数；消费＝到店开单金额合计、消耗＝到店核销（耗卡）金额合计；**客单价＝消费合计 ÷ 到店总人次**（多店汇总按**加权**计算，不是各店客单价的平均）；环比＝与上一期比，同比＝与去年同期比（仅按月）。
**目标参考线**：目标进度来源多画一条**虚线＝目标**（按门店分列时为"各门店目标合计"），明细表多「目标 / 达成率」两列，信息条显示最新一期达成率；不同指标单位不同（元 / 人次 / 人 / 个），**不跨指标相加**。

**角色适配**：店长（权限锁定本店）默认"汇总"看本店走势；区域总监可在「筛选门店」限定本市场后切"按门店分列"横向比门店；总部看全国。权限完全复用现有门店多选与账号规则（**例外**：经营数据主表来源按其 Excel 模板自带门店集取数——该明细页本身也是这个口径）。

#### 5.7.3 同源取数约定（口径不分裂）

- 分析页与明细页**同源取数**：以「全局筛选期间所在月」为**基期**（期次系数＝1），因此**基期数值与对应的明细页完全一致**，其余期次按同一套走势口径外推（演示数据可复现，便于演示时对照勾稽）。
- 切换「数据来源」只换指标字典与取值口径，**页面不换、门店 / 期间 / 图形上下文不丢**；指标自动回到该来源的首个指标。
- 正式版：由**后台按期间聚合**提供（含权限过滤），前端只负责渲染。

#### 5.7.4 为什么这样分层（可演进）

- **不为每张明细表建分析页**：页面数与报表数解耦——报表增长，分析页始终是 1 个，避免"N×N"页面爆炸与多套口径漂移。
- **再加分析对象＝只加一个来源页签**：例如将来给「员工管理 / 卡项与产品 / 顾客管理」做分析，只需补一份"指标字典 + 取数口径"，并给对应明细页加一个「📈 看趋势」入口。
- **跨板块分析变多时可升级**：把该页提升为一级「分析中心」，页内「数据来源」页签承载更多来源，**结构不变、不返工**。

### 9.3 口径与实现约定

1. **提成＝分配金额 × 提成点**；业绩提成来自现金单的销售分配、消耗提成来自耗卡核销的服务分配 —— 两笔**分开统计、分色展示、分开下钻**。
2. **提成点来源**：正式版由后台「提成配置表」按 **门店 × 岗位/美容师 × 项目类别 × 订单类型** 返回（真实系统已有该配置，原型不做配置页）；原型按「岗位 + 项目类别」模拟。
3. **数据来源**：小程序开单 / 核销实时写入；正式版按日 06:00 汇总更新，原型为可复现的演示数据。
4. **权限**：完全沿用现有门店多选与账号规则（见第四节）。
5. **可扩展**：若要按"订单 / 项目 / 品项"维度看提成，只需在本板块加子页 —— 计算已按"逐单 → 汇总"两层设计，不返工。

## 十、需要与运营/开发确认的事项（原型中未拍板）

1. 「服务类字段」（自耗服务 / 他耗服务 / 生态合作服务）原型已按**金额（元）**统计、标题不带“业绩”二字；请业务侧最终确认该口径与后台实际取数口径一致。
2. 视角②是否需要像视角①一样，把每个品项也按「业绩 / 服务」拆开展示？（现状：视角③已按**一级 → 二级**拆解品项，但仍是**业绩口径**）
3. 顾客频率表横轴是否一定按自然月 1~N 号？如果用户选择的起止日期跨月，是禁止还是按月拆分统计？
4. 顾客电话在列表中是否要脱敏显示（如 `138****8888`）？
5. 导出 Excel 是否需要两个视角、两种页面都支持？
6. 「目标填报」待确认：① 填报粒度是否只要“本月目标 + 各周目标”，还是也要**每日目标**？② 是否要**审批流**（美容师提交 → 店长审 → 区域/总部审，驳回可改）？③ 是否需要**历史版本/修改留痕**（谁在何时把目标从 A 改成 B）？④ 门店目标与美容师目标之和是否要做**一致性校验**（门店目标 = 各美容师目标之和）？⑤ 目标是否需要**按品项/业绩类别拆分**（如现金业绩、耗卡业绩）？
7. **多指标口径待确认**：① 指标清单是否就是这 5 项，是否需要**更多指标**（如现金业绩、耗卡业绩、到店人数、复购率）或**按品项拆分**？② 指标是否有**主次 / 权重**（如业绩为主指标，其余为辅），报表是否需要一个“综合达成分”？③ 指标单位与取整口径是否与后台一致（金额＝元且按百元取整？计数＝整数？）④ 指标是否随**角色/区域**不同而不同（如区域总部看区域汇总口径、美容师只看个人）？⑤ 是否需要**指标看板**：把“未达标指标”自动置顶或红点提醒？
8. **顾客频率表口径待确认**：①「低频 / 中频 / 高频」的分档阈值（原型按 **1~2 次 / 3~4 次 / ≥5 次**）是否符合业务口径？②「消费」与「消耗」的差异口径（原型按“每次到店**开单金额**”与“**核销 / 耗卡金额**”区分）是否与后台取数一致？③ 本月**未到店**顾客（0 次）是否需要一个单独的“流失 / 沉默预警”指标卡？④ 到店次数是否按“人头到店天数”还是“服务单次数”统计（同一天多次到店怎么算）？
9. **经营分析口径待确认**：① 趋势的"月"按**自然月**还是**经营周期月**（26 日~次月 25 日）？② 是否需要**按季 / 自定义期间**？③ 同比是否要按"同期可比天数"折算（如 2 月对 2 月、含节假日的月对月）？④「按门店分列」上限 8 条是否够用，是否需要"排行榜 / 只画 Top N / 只画异常店"？⑤ 是否需要把趋势做成**卡片式看板**（多指标小图并排）？⑥ **「数据来源」是否就这 4 个**（日常数据一览表 / 顾客频率表 / 经营数据主表 / 目标进度表），后续是否要接 顾客管理 / 员工管理 / 卡项与产品？⑦ **目标进度的"按周"何时补**（原型只做月度口径，周目标走势需后台按周聚合）？⑧ 目标来源的"目标"是否需按**季度拆分**（主表模板中的被经营目标是季度口径）？⑨ 经营数据主表来源固定用模板自带的门店集（示例为自贡市场），正式版应改为**按账号权限 + 筛选门店**取数？
10. **员工收入（提成）待确认**：① **美容师/店长视角**是否只看本人（当前店面视角看全店、可按员工筛选，是否需要"只看我自己"的硬限制）？② 提成点是否就是按 **岗位 + 项目类别** 分档（真实「提成配置表」的维度与优先级：门店/人、项目、订单类型，谁先命中？）③ **耗卡核销单**的「实收金额」是否确认为 0（原型按卡内已付处理），还是需要展示当次核销额？④ 提成是否需要**结算周期 / 封账**（按日看的是过程值，发薪口径可能按月封账）与**退回/退款冲减**（退单后提成如何回冲）？⑤ 是否需要**矩阵的"色阶/热力"模式**（按当日提成高低深浅着色，便于一眼扫高峰）？⑥ 是否需要**提成排行 / 异常提醒**（如某员工消耗提成骤降）？⑦ 提成明细是否需要**合并展示同一订单的多人分配**（一单分给多人时，谁分多少）？⑧ 矩阵列的日期口径是否沿用"开始日期所在自然月"（跨月区间目前只展示当月）？
11. **「业绩 / 服务」四分类口径待确认**：① 业绩与服务现按 **自销自耗 / 他销他耗 / 他销自耗 / 生态合作** 四类拆，是否还要补上 **自销他耗**（自己卖、他店耗）凑成完整 2×2？② 「自销 / 他销」按**开单门店**还是**开单员工**判定？③ 「自耗 / 他耗」按**核销门店**还是**顾客归属门店**判定？④ 生态合作业绩 / 服务是否要再拆到合作方（渠道或门店）？⑤ 这 4 类是否要与小程序开单页的「业绩归属」选项**一一对应**（避免录入口径与统计口径不一致）？⑥ 视角③的「二级品项」是否就是【品项分类】的第二层，是否需要支持**第三层**？⑦ 视角③是否需要同时给出**一级小计列**（现在只有表内分组的组头，没有每组的合计列）？
12. **顾客剩余卡项清单待确认**：① 「剩余次数」口径是否含**赠送 / 补送**次数、是否要扣**冻结 / 过期**卡项？② 单元格只打 ✓ 还是要直接显示**剩余次数**（现在次数在悬停提示与行「剩余次数」里）？③ 是否还要看**剩余金额 / 剩余价值**（不只是次数）？④ 是否要标出**沉睡但有剩余**的顾客（长期未到店，提醒回访）？⑤ 「未买过」是否要区分**没买过该一级品项**与**没买过该二级品项**？⑥ 真实【品项分类】可能几十列 → 是否需要「按一级只显示组头 / 分组可折叠 / 只看有剩余的列」？⑦ 导出 Excel 是否要把 ✓ 展开成「剩余 N 次」？⑧ 顾客范围是否要支持**只看某等级 / 某卡类型**的顾客？

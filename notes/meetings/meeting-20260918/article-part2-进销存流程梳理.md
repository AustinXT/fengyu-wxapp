## 一、层级与流转全景

```
供应链（品项公司 / 总部）
   ├─ 对外采购（按固定批次，不按供应商拆分）
   ├─ 采购入库（可分批录入，生成批号）
   └─ 发货（物流中心配货单，以区域为单位）
        ↓
市场（区域）
   ├─ 入库（引用配货单，数量金额不可改）
   ├─ 配货到门店（价格可再次调整）
   ├─ 自建商品与自行采购（供应链不管）
   └─ 市场间调货（先出后入，可减价不可加价）
        ↓
门店
   ├─ 入库（引用市场配货单，只见本店单据）
   ├─ 出库（顾客领走 / 报损）
   └─ 盘点（每月至少 3 次）
```

**贯穿全链条的一条铁律**：**价格在每个层级都会变一次**，且历史单据必须保留当时价格。

## 二、逐环节业务口径

### 2.1 门店报货单

- 报货日期**固定**：每月 5 号、15 号、25 号。偶尔会加批次，但时间全公司统一。（暂时系统上不用限定时间）
- 支持草稿：可先添加不提交，确认好再选"是否提交 = 是"。
- 门店只需看到"报什么货、报多少数量"——**金额、供货商这些字段不要给门店看**。

### 2.2 市场汇总（市场财务 / 主管）

按日期提取本市场所有门店的报货单：

| 区块 | 内容 |
|------|------|
| 主表 | 按产品合计：各店提报数量合计、本市场库存、**采购数量**（不填 = 不采购，因为自己有货） |
| 明细 | 以门店为单位，仅作参考 |
| 价格 | **市场单价** = 区域向供应链采购的价格 |
| 单价优惠 | **不可手填**，由「报货福利」自动提取 |
| 实际单价 | = 市场单价 − 优惠；× 数量 = 产品成本 |
| 门店单价 | 额外做的参考列，不影响业务 |
| 已废弃 | 地租费等历史字段可以不要 |

**报货福利机制**：供应链新建的优惠方案，可指定**区域 + 商品**，带阶梯（如满 10 套单价降到多少）。市场汇总时选"是"，系统根据**商品编号 + 市场 + 日期**自动判定该产品是否有优惠。

提交后表单**自动锁定**，不能再修改。所以存在一个"可做不提交"的草稿窗口。

### 2.3 品项公司报货需求

供应链办公室自己的需求（"有时候也是我，比如说我自己要买，我会提一些需求"）。

### 2.4 汇总市场报货单（供应链视角）

所有市场统一日期做完后，供应链把**全国所有区域**同一日期的报货汇总到一张表。

**这张表的唯一用途**：供应链会计看**每个市场要收多少钱**，导出后作为收款凭证。

当场发现的问题与修改：

| 问题 | 修改 |
|------|------|
| 缺区域名称 | **必须增加区域名字段**，才能区分是哪个市场的 |
| 有供应商字段 | **去掉**——这一步不按供应商区分 |
| 有可编辑的采购数量 | **去掉**——汇总只是看，不做动作 |
| 只有合并金额、没有明细 | 改成**明细形式**（南昌可能有 10 个报货单，不同批次要能看清） |
| 缺单价 | **必须带每项单价**，且做**价格快照**——下个月改价不能影响之前已收完钱的单据 |
| 筛选 | 时间筛选 + 供应链/市场筛选；明细做成表格显示，支持导出 |

夜航星确认："这里的价格相当于从商品那边做了一个快照……这些单据对这个价格做一个快照。"

> 注：报货福利改价也算改价格，同样受快照保护。

### 2.5 创建采购订单（本节最大的口径纠正）

**采购订单 = 市场汇总 + 品项公司需求**，两个来源合并成一张单。

当前系统把它做成了两个菜单（「供应链采购订单」和「创建采购订单」），字段一模一样，只是来源不同。**张凯要求直接合并为一张**，在单据那页加一个字段区分需求来源（市场 / 品项公司）——"合并之后，品项公司也相当于一个市场，他就并在市场名字那一列了"。夜航星确认可行。

与汇总单的差别只有一个：**多一个「采购数量」字段**——核对自有库存后，市场报上来的不一定都要对外采购（"因为我有啊"），品项公司自己提的反而可能没有必须采。

#### ⚠️ 关键纠正：采购订单**不按供应商拆分**

| | 系统当前设计 | 凤御实际业务 |
|---|---|---|
| 组织方式 | 按供应商分别下单 | **按批次**：9/5、9/10、9/15、9/20、9/25、9/30 固定批次 |
| 一批次 | 20 个供应商要建 20 张单 | 所有供应商并在一张 |
| 会计关注 | 每个厂家多少钱 | "我只需要知道我这一批对外采购是多少，不需要知道每个厂家" |

张凯："采购订单为什么要一个一个采？……我们时间都有规定的，不是他随时都可以。"夜航星理解后确认合并。

**单据关联方式**：采购订单**只按日期汇总**报货单，不逐单引用（9 月 15 号那批，品项公司没提需求就只有市场的；9 月 10 号那批能看到品项公司的引用）。

### 2.6 供应链采购入库

- 支持**分批次录入**（采购 20 个，先录 3 个、再录 6 个，剩 17→11 待处理）；
- **批号自动生成**，每次流转都算一批、都有编号（夜航星确认"跟踪不了每一个产品，是一批一批的"，张凯认可这样反而更准确）；
- 入库时多一个**优惠字段**：商品档案里记的是标准进货价，但对外采购价无法保证统一（厂家做活动会给优惠）。**不改商品原始属性**，在入库单上填优惠，体现这一批真实的入库成本；
- 入库需填有效期。

### 2.7 品项公司发货单（= 物流中心配货单）

**以区域为单位**。操作顺序：

1. 选收货方（哪个区域）；
2. **引用市场的原始报货单**（不是汇总单）——比如"自贡 9 月 10 号的报货单"，系统提取当时的报货数量；
3. **从库存按批号逐行选**要发哪一批（如库存显示"草本套 59 个"，可能有好几个批号）。

**分批发货规则**：一行不能对应多个批号。若市场报 30 个而某批号只有 10 个，就选该批号填 10，然后**新建一张表单**，系统会提示"还有 20 个没发"，再选另一个批号。库存不足时可以把提取出来的多余行删掉，只发有货的部分。

**赠送处理**（夜航星追问了三轮）：

| 问题 | 口径 |
|------|------|
| 赠送怎么录 | 报货单里没有，发货时**自己新增几行**，价格为 0 |
| 数量对等吗 | **不对等**。报 10 个可能发 12 个——采购时厂家给了优惠，发货时才决定赠送 |
| 会平摊单价吗 | **不会**，"赠送的价格就更透明了" |
| 怎么锁定哪件是赠送 | 商品有一个「是否赠送」属性，**从采购入库时就已限定，一直跟着批号走**；赠送是**独立批号**，不与非赠送并行 |

### 2.8 市场入库

- **不是新建，是走流程**：品项公司发货是一个流程，市场这边点进流程即可（流程进行中会在右上角提示）；
- 引用**物流中心配货单**，本次入库数量必须与发货完全一致（数据是跳出来的不是填的）；
- **金额等字段不可修改**——"入库的动作他是不能改价格的"；
- 同时还要**关联市场报货单**：因为一个报货单供应链可能分好几次发货，需要能查"这批报货累计入库多少、还有哪些没录、是否全部录完"。这个关联纯粹起追溯作用。

### 2.9 市场配货到门店

- 以门店为单位；
- **门店可以不提需求**，由市场直接发货（引用报货单栏为空即表示门店没提需求）——夜航星现场观察到"没有引用报货单的更多一点"，张凯确认市场直接发货是主流；
- 若门店提了需求就引用，自动跳出报货数量，填配货数量；
- 默认价格 = 商品属性里的**门店进货价**（即区域应收门店的钱），作为「应收金额」；
- **主管可手动调价**：配货时可填优惠。黄色字段显示该批号市场的**实际进货成本**供参考——例如某批市场进价为 0（品项公司做活动），主管就可以自行决定给门店也算 0（填优惠 27）还是照收 27；
- 这些参考价不影响数据，只供区域主管配货时查看。

### 2.10 门店入库

- 引用市场配货单，前台点开是一个列表，**只看得到属于本店的单据**（单据编号带门店字段）；
- 正常情况下**入库数量不可编辑**——"他的主管给他发多少货，他默认就确认数量，直接保存"（当前可编辑是因为张凯后面改了权限）；
- 保存的作用就是让商品进入这家店的库存表。

### 2.11 门店出库

绑定业务场景：

**① 顾客领走**

选顾客 → 选销售单（只有顾客有剩余未取的订单才出现）→ 显示订单详情与销售流水号 → 领取 → 与库存商品名核对一致（防止选错）→ 填出库金额。

**出库金额 = 该商品顾客实际售价**，用途是**给店长算提成**。业务含义：预存款变成收入，即"消耗"。

**② 报损**

门店把产品拆掉了也叫报损，**走正常出库**（张凯特别澄清："那个报损不算损耗呀，报损就正常出库"）。

### 2.12 盘点

| 层级 | 频率 |
|------|------|
| 门店 | 每月至少 3 次（因系统切换，这两个月没做） |
| 市场 | 每月 1~2 次 |

- 盘盈按**标准价**入账；
- 口径："**你可以多，但是你不能少，少了我要罚你钱**"；
- 盘盈原因往往查不出来——"门店都是没有专业会计的，店长只告诉你我就是多了，我也不知道为什么多了"。夜航星认为"要找出多的原因这个成本太大了"，三方共识是**找得出就找，找不出就盘盈纠正进去**。

### 2.13 货款结算（分院货款结算单）

按市场提取整月，列出每家店的数量、金额。

**⚠️ 时间口径**：**以市场发货（配货）时间为准，不管门店是否及时入库**。

> "主管做了发货单之后，前台不一定及时做入库单，那么无所谓……我的发货时间在 8 月 1 到 8 月 31 号这个期间，就算你没入库，我也要算门店的钱。"——这是内部规定。

优惠金额来自区域配货时填的优惠字段，会影响门店的应付金额。**各店股东或店长每个月看这张表看得很仔细。**

### 2.14 跟进查询表

| 报表 | 用途 |
|------|------|
| 分院未入库明细 | 区域发了货、门店没入库的清单 |
| 市场入库情况查询 | — |
| 全产品进出明细 | 按市场 + 商品编号 / 批号（二选一）查从头到尾的全部流水，用于排查为什么会多或少 |

### 2.15 库存产品转换

- **仅供应链可做**，市场和门店不可转换；
- 不引用批次，选现有库存的**产品批号** + 转换数量 + 目标商品（目标商品必须在产品列表里，不能凭空造）；
- **生成新批号**（库存上新产生的库存）；
- 价格自己填，**上下必须对等**（成本守恒）；
- 支持**多对多**：如 13 个 A + 13 个 B → 13 套；25 个拆成 12 + 13；
- 也支持**拆分**：厂家一盒内含两件（内裤 + 连体衣 + 文胸），仓库拆成单件卖；或进货是一瓶、拆半瓶卖给顾客；
- 保存后原商品库存变负、目标商品库存增加。

**业务原因**：供应链视角可以零散进货，但卖给顾客是打包的——如「维乐」套装包含若干耗材 + 按摩油，拼在一起才是一套，没法零散卖。

### 2.16 市场 / 门店自建商品

- 区域可在市场库存里**自行建档**（文具、耗材等统一采购），**供应链不管**；
- 若门店字段选本区域名字，则该区域下所有门店都能选到；
- **无流程**——直接增加库存即可，没有谁给他配货，但可以随其他商品一起发下去；
- **不能做转换**。

### 2.17 市场间调货

- **先出后入**：由调出方先建出库单，选择对象 + 库存批号；
- 金额跳全产品资料表里的**标准价**；
- **可以减价，不能加价**——"加价别人也不会要嘛"；可以优惠到 0（因为供应链发过来时可能本来就是赠送的）；
- 黄色参考字段告诉区域主管"这批进过来当时花了多少钱"，由其自行决定调给别人收不收钱；
- **市场与市场之间独立结算**。

## 三、新系统当场发现的问题清单

| # | 问题 | 处理 |
|---|------|------|
| 1 | 「供应链采购订单」与「创建采购订单」两个菜单字段一模一样 | 合并为一张，加来源字段 |
| 2 | 采购订单按供应商拆分 | 改为按批次合并，去掉供应商 |
| 3 | 汇总表缺区域名、缺单价、无明细、有多余的采购数量与供应商 | 逐项调整（见 2.4） |
| 4 | 单据全部并在「单据中心」，找不到某单走到哪个环节 | **每个动作独立列表页**——两个 tab：列表 + 填报，点列表进去填报 |
| 5 | 单据全标「已完成」，供应链采购时分不清哪个已采购 | 加筛选功能 |
| 6 | 发货时看不到发给谁 | 十几个区域报上来会分不清，需体现区域 |
| 7 | 发货依据不明确 | 张凯定：**发货引用市场报货单**（依据"要发什么"而非"收到了什么"） |
| 8 | 网页版不好用 | 希望做成表格样式，点进来能看到每个订单的情况 |
| 9 | 商品新建页所有角色共用，市场/门店新建时也能选供应链 | 可做限制（当前只在查看时过滤） |
| 10 | 商品下拉太长，几百个商品滑不动 | 加检索功能 |
| 11 | 货款结算单需按时间筛选、合并到一起 | 加日期筛选 |
| 12 | 供应商字段应自动带出 | 后面可让它带出来 |
| 13 | 页面字号异常、缩放比例不显示 | — |

**实跑结果**：洗面奶（品项公司需求来源）与精华液（市场报货来源）两条链路，精华液跑到入库环节卡住——市场报货已完成、采购订单已完成，但入不了库。夜航星判断"可能做漏了"，未当场定位。邵冬确认："没跑通是吧。"

张凯当场说明了根本困难："如果让我去单据中心里面找，我就不知道它走到哪个环节了。"——这正是第 4 条要独立列表页的原因。

**后续动作**：张凯把 WorkFine 账号给夜航星（"没有账号，拆起来太费劲了"）。

## 四、穿插的业务背景

### 4.1 工资核对的现状与风险（张凯）

- 本月工资"很多手工核的，因为里面有很多细节，但数据对不上"，所以一直追着要导出订单再人工核；
- **风险不在工作量，在于机制**：美容师实时能看到自己的提成，如果看到的和最终发的不一样，大家就会认为"订单错了没关系，反正财务会手动加上"——"这就是一个很严重的性质问题，那大家就不喜欢用这个东西了"；
- 张凯的立场：必须严肃地告诉员工"**美丫丫上面显示 1900，我就给你发 1900**，不要回头跟我说错了让财务补"，只有这样他们才会认真对待开单。（他为此还批评过[李广硕?]："那你要手动算可以，那你以后都去手动算，你不要用美丫丫了。"）

### 4.2 权限观察

单据中心把所有单据并在一起后，权限能否分清？夜航星确认可以——按市场、门店区分，与订单那边类似。以门店身份进去只能看到本店的，管理员进去看到的才多。

### 4.3 邵冬对这套流程的评价

"（WorkFine）不仅是表格，有做表格的也没有做成你那么好。"张凯自评："我这个逻辑还挺复杂的，价格到每个层级都可能会变。"

邵冬问"像你这样跟万总讲逻辑他们听得懂吗"，张凯的回答是他们听不懂也不管——引出一段背景：凤御的账当年已经完全崩掉，才把张凯从另一个区域调来负责。

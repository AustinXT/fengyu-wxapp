## 一、库存管理

### 供应链三级架构

供应链分为三个层级：**总部（供应链）→ 区域（市场）→ 门店**。

报货流程自下而上：
1. 门店每五天提交报货单
2. 区域财务汇总 → 区域有货直接发，无货则向总部生成"市场报货单"
3. 总部汇总全国采购需求 → 按市场分别发货

发货流程自上而下：总部 → 区域入库 → 门店入库。

### 调货规则

| 调货类型 | 规则 |
|----------|------|
| 同区域门店间 | 可自主调货 |
| 跨区域门店间 | 不可直接调，须经各自区域总部中转 |

调货操作：只能由调出方发起，调入方根据调出单做调入 — 不能主动做调入单。

### 门店出入库场景

| 类型 | 说明 |
|------|------|
| 报货入库 | 区域配货后门店入库（主管也可主动发货，如耗材） |
| 销售出库 | 顾客凭销售单领走产品，无销售单不能出库 |
| 调货出入库 | 门店间同级调拨，调出/调入为同一张表 |
| 退货 | 退给主管（跨区域调货、不再使用、产品损坏等） |
| 领用出库（院报损） | 大桶/套盒产品拆封给顾客使用（如洗发水、精油） |

### 结论

- 当前只需流水表，不需要库存积累表（商品库存虚标）
- 小程序端做三级库存架构复杂度极高（还涉及货款计算），放在**下下个迭代**评估
- 数据操作的排他性原则：一个功能要么在小程序操作，要么在 WorkFine 操作，不能两边同时操作（否则数据一致性有问题）
- 若小程序端实现困难，退回原方案：小程序只做表单提交，库存管理在 WorkFine 完成

## 二、经营数据定义

### 顾客分类标签

| 标签 | 定义 |
|------|------|
| 注册 | 仅注册 |
| 体验客 | 购买不算业绩的卡（68/99 元卡） |
| 流量客 | 有消费但未达会员标准 |
| 会员 | 消费达到会员标准（1980 元） |
| **新客** | 当月消费首次达到会员标准的客人（毛增加，不扣减流失） |

### 客流 vs 客量

| 指标 | 计算单位 | 去重规则 | 数据来源 |
|------|----------|----------|----------|
| 客流 | 人次/日 | 同日去重（一天多个服务单只算一次），月内累加 | 服务单 |
| 客量 | 人数/月 | 全月去重（一个月来十次只算一人） | 服务单 |

### 业绩指标

| 指标 | 定义 | 数据来源 |
|------|------|----------|
| 实收业绩 | 销售类单据（销售单/转换单/回款单）的实际收款金额，不减退单 | 销售单 |
| 消耗业绩 | 服务单中划卡消耗的金额（如 2000 元十次，做两次消耗 400 元） | 服务单 |

### 保有会员（到店时间标签）

基于**最后一次服务单时间**判断（以服务为准，下单不算）：

| 标签 | 条件 |
|------|------|
| 活跃会员 | 3 个月内到店 |
| 睡眠会员 | 超过 3 个月未到店（即将流失） |
| ... | 另有 6 个月、1 年、超 1 年等分级 |

标签分类表张凯一方仍在规整中，后续补充。

## 三、员工绩效与提成 ✅

### 提成结构

每个产品需要配置**两个字段**：

| 字段 | 说明 |
|------|------|
| 固定手工费 | 固定金额，不随卖价变化（低价卡/引流卡适用）；无则填 0 |
| 消耗提成比例 | 划卡金额 × 比例（正常价格产品适用） |

两者可同时存在，合计为员工该次服务的提成。

**不能用单一比例替代**的原因：卖价可能有临时优惠（今天优惠 100，明天优惠 200），价格变动导致比例不准确。

### 销售提成分类

销售类单据按商品品牌/类别分四种提成：

| 类型 | 含义 |
|------|------|
| 自销自耗 | 自己卖 + 自己做的生活美容项目 |
| 自销他耗 | 自己卖 + 别人做 |
| 他销自耗 | 外部合作（安吉丽、医美等）+ 自己做 |
| 他销他耗 | 外部合作 + 别人做 |

四种类型提成比例可能不同，需要分别配置和统计。

### 人效指标（英雄榜）

| 指标 | 来源 |
|------|------|
| 业绩（金额） | 销售单分配 |
| 消耗（金额） | 服务单划卡 |
| 划卡数（次数） | 服务单中消耗的项目次数 |

## 四、数据展示方案

### 核心矛盾

管理层需要多维度汇总数据（市场/门店/时间交叉），但实时计算开销大、小程序加载慢。

### 最终方案

| 场景 | 平台 | 说明 |
|------|------|------|
| 员工个人数据 | 小程序 | 本月累计，不支持时间筛选 |
| 月底薪资 | 小程序推送 | 月末推送一次，次月刷新为零 |
| 管理层汇总 | 分析师（BI） | 复杂分析、导出，通过公众号菜单或浏览器访问 |
| 人事/财务操作 | 小程序后台（Web） | 导出数据、编辑员工档案等 |

### 技术限制

- 订单和护理单两张表数据量大且持续增长
- 多维度（市场/门店/时间/商品类别）交叉查询无法建固定视图
- 小程序不适合做缓存，不做分表
- 加载速度是硬约束：汇总查询耗时长，并发查询会卡死

## 五、经营周期 ✅

凤御经营周期为**每月 26 号 ~ 次月 25 号**（月底留时间开会做规划总结）。

**当前决定**：先按**自然月**实现。

原因：
1. 非自然月的时间筛选控件不好做
2. 实时计算在非标准时间窗口下更加复杂
3. 1980 元会员标准将来可能变化，需做成可配置项

## 六、权限设计 ✅

### 双维度权限模型

| 维度 | 值 |
|------|------|
| 地理层级 | 总部 → 市场 → 门店 |
| 职能角色 | 经理（全部权限）、财务（可看汇总）、人事（可编辑员工）、产品（可编辑商品/营销）、员工（只看自己） |

权限 = 层级 × 角色。如"市场·财务"可看所属市场的财务汇总数据。

### 典型角色映射

| 实际岗位 | 权限配置 |
|----------|----------|
| 基层美容师 | 门店·员工 |
| 门店经理/店长 | 门店·经理 |
| 市场总监 | 市场·经理 |
| 总部人事 | 总部·人事 |
| 总部财务 | 总部·财务 |
| 商学院/运营 | 总部·产品 |
| 后台管理员 | 小程序后台独立角色 |

### 待解决：区域经理（"3.5 层"问题）

南昌等大市场存在"区域经理" — 管 3-5 家店，高于店长但低于市场总监。

| 问题 | 说明 |
|------|------|
| 层级增加 | 三层变四层，所有统计接口查询复杂度上升 |
| 性能影响 | 层级查询是高频操作，四层会让所有接口变慢 |
| 权限复杂度 | 不能把权限做成列表（也影响加载速度） |

**当前状态**：暂不支持，需另行讨论。权限问题是当前最优先待定事项。

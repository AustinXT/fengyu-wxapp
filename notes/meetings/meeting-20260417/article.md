**议题**：数据中心页面 4 大板块（客量/销售/员工/品项）字段定义、权限划分，以及 4 月 16 日最新发版后的开单流程验收

## 一、总体架构的重大调整

会议开场，贺东群按其准备好的 Excel 原型逐版块讲解数据中心。讲解过程中反复出现两个核心矛盾：

1. **宽表 × 小程序** —— 贺东群的表格字段横竖跨度都很大，每个板块都会一路横拉十几列（会员注册 → 有效保有 → 一次到店 → 二次到店 → 消费分档 …）。夜航星提醒这种"宽表"在手机屏幕上根本摆不开，即便把表格剪短，"一行也只能放三到四列"。
2. **死数据 × 实时计算** —— 有效保有会员、沉睡冰冻休眠这些指标口径上都是"以整月为单位"（如"前 3 个月至少到店一次"），属于每月定格的死数据；但再往下的"当月一次到店/二次到店"又必须实时更新。夜航星提到过往测算：一次复购率聚合仅数据层就要 23 秒，"整张页面要全量算出来，加载会很慢"。

双方顺着这两条矛盾，得出本次会议最重要的架构决定：

### 决定：外部端数据中心取消，嵌入"分析师"

1. **原本规划的"管理后台 (外部端) 数据中心" 板块不再单独实现**，改为把已有的 BI 平台"分析师"嵌入管理后台
2. 分析师本身支持缓存、图表渲染、导出，宽表、复杂聚合都由它承担
3. 权限复用小程序/后台这边的账号体系，无需在分析师另建一套用户管理（邵冬尾段补充：此方式避免重复建权限）
4. 小程序端只保留**简版数据看板**，展示核心指标

邵冬确认这个方向，但同时提醒张凯：分析师的合同还没签，要尽快走完商务流程。

## 二、小程序简版看板的方向

夜航星建议参考股票类小程序的思路：

- 小程序端不展示明细表，只列关键指标
- 所需指标由财智部（贺东群）从完整版中挑选
- 表格单列宽度要压短，一行不超过 3~4 列；必要时"同类拆分多张表、下滑展示"
- 移动端体验参照 WorkFine 移动端——"两列常态、四列极限"（邵冬补充）

## 三、客量板块（会议中用时最多）

### 快捷筛选与时间口径

- 上方快捷按钮：今日 / 本周 / 本月 / 今年，同时支持自定义时间范围
- 数据中心内每个指标必须把"分母定义"（截止时间点）明确写在口径旁边，避免阅读歧义

### 指标口径（贺东群说明）

| 指标 | 计算口径 |
|------|---------|
| 会员注册人数 | **本月**内单笔消费满 1990 元即注册为会员，动态、随时更新 |
| 有效保有会员 | **前 3 个月**（整月口径）至少到店一次的会员，数据按月定格 |
| 本月一次到店 | 在"有效保有会员"基础上，本月到店一次的人数，实时 |
| 本月二次到店 | 同上，到店二次的人数，实时 |
| 沉睡 / 冰冻 / 休眠人数 | 来自顾客管理的分类结果，截止**上月底**的快照 |
| 当月激活人数 | 上述沉睡/冰冻/休眠中本月又到店的人数，实时 |

### "有效保有会员"的时间窗澄清

有效保有会员以**整月**滚动，不以日算：

- 4 月 5 日或 4 月 17 日筛选，跳出来的都是 1、2、3 月里至少到店一次的人
- 2 月 5 日筛选，则口径变成 11 月、12 月、1 月这三个月至少到店一次

夜航星在此追问："那不是和你上面那个时间筛选有矛盾吗？"张凯的回答是：**此指标规则和筛选日期没有强绑定，它由"滚动 3 个月"本身定义**。

### 流量客的位置

除了会员客，还要在明细区最后一排单列"流量客人数 / 流量客人次"——即未成为会员但有到店护理的顾客。

### 消费分档（会员经营人数）

明细区下半部分按会员消费总额分档：<1990 / 1990~5000 / 5000~1万 / 1万~5万 / 5万以上等（具体档位以贺东群表格为准）。核心口径经张凯确认如下：

- 档位里只统计**会员客**，流量客不并入
- 档位金额 = **筛选周期内**的累计消费（非历史累计）
- 筛选 3 月 1 日~31 日，则：3 月 31 日之前成为会员的人 → 在这段时间的消费求和，落到相应档位
- **新增会员人数**单列字段，与老会员分档并列（避免 3 月刚入会的客户混到老会员档位里）

贺东群补充：实际运营里 "档位以年为主"，月度档位保留是以防万一。

## 五、员工板块

### 字段定义

| 字段 | 说明 | 状态 |
|------|------|------|
| 员工数量 | 全员人数 | 保留 |
| 店长人均员工数 | 店长管理半径 | 保留（原口误"管理技师" → "管理技师人数"即技师人数，澄清为同概念） |
| 店长收入 | —— | **删除**（早前讨论已否决，贺东群笔误保留） |
| 技师数（美容师 + 养生师） | 不分具体工种 | 保留 |
| 人均业绩 | 原字段"人均总业绩" → 去掉"总"字 | 改名 |
| 人均单号（原文"人均10号"） | 服务单数 / 人 | 保留 |
| 人均收入 | —— | 保留 |
| 人均会员量 | —— | 保留 |
| 人均项目数 | 按服务单求和 | 保留 |

### 门店与员工排名

- 门店排名：按区域汇总
- **权限分层**：
  - 店长：只看到自己门店所在行（其他门店不显示）；如需呈现相对位置，只显示自己的排名数字（如"第 10 名"）
  - 区域经理：所辖区域内全部门店
  - 总监 / 老板 / 财智部：全域
- 员工排名：业绩 = 销售单求和；单号 = 服务单求和；收入 = 提成合计

## 六、品项板块

### 新增一层分类：招牌 / 王牌 / 明星

贺东群要求在现有 2 级品相之上新增业务分类（生美类里的"招牌"、"王牌"、"明星"）。张凯最初建议单独做一级，夜航星提出更简洁的方案：

**方案（夜航星）**：直接把现行的"1 级品相 = 护理项目 / 家居产品 / 充值卡 / 体验卡"中的**护理项目**拆成**招牌 / 王牌 / 明星**三项，和家居产品 / 充值卡 / 体验卡并列（由 4 项变 7 项）。

- 影响面仅限员工端开单页面的分类排版，不影响客户端（因客户端用三层管理模型）
- 现有 2 级品相（面部 / 身体等）保留为细分
- 家居产品不需要同步拆分

张凯一度担心这种调整日后会频繁变动，夜航星澄清："这是初始化做一版，后面不用再变"。张凯确认通过。

### 品相归类表的旧数据

贺东星提到的"曼之语 / 蜜语生机 / 东华神灸 / 新生态"等是按品牌分的旧数据库字段，**不再使用**，本次不并入。

### 品项板块的明细指标

- 持卡人数（按品项疗程卡持有数，贺东群原表误写"存卡人数"）
- 生美招牌复购人数 / 业绩
- 计算方式与销售板块类似，夜航星评价复杂度不高——"之前做复购率时就踩过了，就是求和"

## 会议贯穿的几条原则

1. **宽表不上小程序**：小程序只保留关键指标与简短明细
2. **不重复造轮子**：已有的"分析师"可以承担宽表、缓存、图表、导出，数据中心直接并入
3. **口径必须明确**：每个指标的时间截点、分母范围写清楚，避免阅读歧义
4. **权限按组织单位划分**：不做"美容师-顾客"颗粒度的数据权限
5. **员工端排版变更只做一次**：初始化阶段定型后不再频繁调整

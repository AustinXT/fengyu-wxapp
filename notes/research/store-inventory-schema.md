## 二、各表特征分析

### 2.1 院报货单（S336/M342）— 最简单

- **无批次**：报货时产品还没入库，无批号/有效期
- **无门店**：只有"市场"和"报货分院"（S336 独有 UDF_S_1883）
- **特有字段**：报货是否完成(布尔)、本单数量合计
- **M342 独有字段体系**：只用 1888-1893（产品5字段+报货数量），无 3878/3911/3912 等批次字段
- M342.UDF_M_6122（库存现有数量）**全部为 0**，无实际价值
- M342.UDF_M_6211（市场）96% 有值（明细级市场，与 S336 市场冗余）

### 2.2 院入库单（S539/M540）— 字段最多

- **关联报货**：UDF_S_3685 = 市场出库单号（SCCKD-xxx），连接院报货 → 市场配货 → 院入库链条
- **配货源信息**：市场配货日期(99%有值)、配货数量(100%)
- **签字图**：UDF_S_19043 仅 19% 有值（图片URL）
- **行数最大**：S=7,919, M=32,800

### 2.3 院顾客退货单（S744/M745）— 数据极少

- **仅 4 条记录**（新功能，2024年6月才开始）
- 关联顾客：顾客编号 + 顾客姓名
- M745.UDF_M_14566（出库数量）与 UDF_M_3912（数量）3/4 相同，1 条差异(4 vs 3)
- 院顾客退货是 **入库** 方向（产品从顾客退回门店）

### 2.4 院顾客产品出库（S601/M602）— 字段最复杂

- 关联顾客：顾客编号(FYGK-xxx) + 顾客姓名
- **引用销售单号**：UDF_S_9176 几乎全空
- **M602 独有 8 个特有字段**（其他表最多 2-3 个）：
  - 库存数量(100%)、销售流水号(20%)、剩余可领取(20%)
  - 验证名称(13%)、验证编号(13%)、单次价格(15%)、出库金额(3%)、备注(~0%)
- 是 **出库** 方向（从门店发给顾客）

### 2.5 院退货单（S587/M588）— 退回市场

- **数据量小**：S=86, M=156
- 关联财务：批号单价(87%有值)、退货货款(79%有值)、库存数量(100%)
- 是 **出库** 方向（从门店退回市场）

### 2.6 院产品报损单（S585/M586）— 独特结构

- **S585 无单据号字段**！ 只有 3 个业务字段：报损日期、门店、市场
- **M586 使用完全独立的字段体系**（5172-5181），不与其他表共享 UDF_M_1888 等
- 报损原因 100% 有值，内容丰富（店用/客用/顾客xxx/员工奖励/过期/拆开使用等）
- 是 **出库** 方向（消耗/损耗）
- **数据量大**：M=38,505（所有明细表中最多）

### 2.7 分院调货出库（S548/M549）& 分院调货入库（S612/M613）

- **同一笔调拨产生两条记录**：S548(发出方) 和 S612(接收方) 共享同一 doc_no
- S548 特有：是否确认调货、对方入库已完成
- S612 特有：是否确认收货、收货数量
- 调入/调出市场 + 调入/调出分院 → 完整描述从哪到哪
- M549.UDF_M_5523（库存可选数量）100% 有值

| 原字段 | 原表 | native_name | 合并到 |
|--------|------|-------------|--------|
| UDF_S_3685 | S539 | 市场出库单号(SCCKD) | → related_doc_no |
| UDF_S_9176 | S601 | 引用销售单号 | → related_doc_no（几乎全空） |

### 4.4 状态字段消除

| 原字段 | 消除方式 |
|--------|----------|
| UDF_S_3684（报货是否完成） | → status enum |
| UDF_S_4631（是否确认调货） | → confirmed_at IS NOT NULL |
| UDF_S_4636（对方入库已完成） | → status enum |
| UDF_S_5593（是否确认收货） | → confirmed_at IS NOT NULL |

### 4.5 调拨合并策略

S548(发出方) + S612(接收方) 共享同一 doc_no，合并为单条记录：
- store_name = 发出方门店
- counterpart_store = 接收方门店
- confirmed_at = 接收确认时间
- receive_quantity = 接收确认数量

## 五、PG 表结构设计

### 方案：2 表 + 2 枚举

8 组 WorkFine 表合并为 `store_inventory_orders`（22列）+ `store_inventory_order_items`（22列）。枚举用中文。通过字段合并（5→1 库存字段、2→1 单价、2→1 金额、2→1 关联单号）和消除（is_completed→status、确认布尔→confirmed_at、全零字段）将 nullable 列降至最优。

### 文件清单

- **`db/schema/enums.ts`** — 新增 `inventoryDocTypeEnum`（院报货|院入库|顾客退货|销售出库|退货出库|报损出库|调拨）+ `inventoryDocStatusEnum`（草稿|待确认|已完成|已取消）
- **`db/schema/inventory.ts`** — 新建，定义两张表 + 4 个 TS 类型
- **`db/schema/index.ts`** — 新增 `export * from './inventory'`

### store_inventory_orders（22 列，12 nullable）

## 六、字段映射关键点

- 调拨: S548(发出)+S612(接收) 合并为一条，store_name=发出方，counterpart=接收方
- 报损: S585 无 doc_no → 同步时生成 `BS-{门店}-{YYMMDD}-{RID}`

- WorkFine 系统字段(FILLDATE/RID/OBYID) 不入 PG，仅在同步脚本中用于去重

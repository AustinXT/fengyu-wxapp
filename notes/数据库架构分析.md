## 一、整体架构

### 1.1 表命名规范

| 前缀 | 含义 | 数量 | 说明 |
|------|------|------|------|
| `tb_sys_*` | 系统框架表 | ~156 | WorkFine 平台基础设施（用户、权限、模板、工作流等） |
| `tb_pub_*` | 公共参照表 | 3 | 日期、序号、城市 |
| `UDT_S_*` | 业务主表 (Single) | ~450 | 每个表单实例对应一行记录 |
| `UDT_M_*` | 业务子表 (Multiple) | ~450 | 表单中的明细/扩展数据，每个实例可多行 |
| `UDT_C_*` | 分类配置表 | ~10 | 分类树节点配置 |
| `UDV_*` | 用户视图 | 2 | 数据查询视图 |

共 **1083 张表**，其中业务表单 **202 个**（每个表单包含 1 张主表 + N 张子表）。

### 1.2 字段命名规范

| 前缀 | 含义 | 说明 |
|------|------|------|
| `RID` | Record ID | 记录主键，关联主表与子表 |
| `OBYID` | Order By ID | 排序标识 |
| `UDF_S_*` | 主表字段 (Single) | 存在 UDT_S_* 表中 |
| `UDF_M_*` | 子表字段 (Multiple) | 存在 UDT_M_* 表中 |
| `UDF_V_*` | 视图字段 | 组合视图中的字段 |
| `FILLUSERID` | 填报人 ID | 系统字段 |
| `FILLDATE` | 填报日期 | 系统字段 |
| `LOCKSTATE` | 锁定标识 | 表单是否锁定 |
| `REPORTSTATUS` | 表单状态 | 表单审核状态 |

### 1.3 主子表关联机制

- 主表 `UDT_S_*` 通过 `RID` 与子表 `UDT_M_*` 的 `RID` 一对多关联
- 一个业务表单 = 1 张 `UDT_S_*` + N 张 `UDT_M_*`

### 5.3 写入注意事项

1. **RID 生成**: 主表和子表共享同一 RID，需先 `SELECT MAX(RID)+1` 或使用数据库序列
2. **编号生成**: 销售单号 (`FY-XSD{YYMMDD}{序号}`)、销售流水号 (`XSLSH-{YYYYMMDD}{序号}`) 需保证唯一
3. **系统字段**: 写入时需填充 `FILLUSERID`、`FILLDATE`、`LOCKSTATE`、`REPORTSTATUS` 等系统字段
4. **枚举值**: 所有枚举字段的值必须与 WorkFine 中配置的选项完全匹配（如"是"/"否"、业绩类型等）
5. **金额计算**: 确保 `收款合计 = Σ(收款方式.金额)`、`本单业绩 = Σ(销售明细.实收金额)`

### 5.4 日历视图数据来源

员工端日历需要按日展示顾客消费：
- **数据源**: `UDT_S_209` (销售单主表)
- **日期字段**: `UDF_S_350` (日期)
- **金额字段**: `UDF_S_844` (本单业绩) 或关联 `UDT_M_213.UDF_M_399` (实收金额)
- **顾客关联**: `UDF_S_1485` (顾客编号)
- **筛选条件**: 按门店 + 日期范围

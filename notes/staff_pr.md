# 员工端（B端）产品需求

> 角色：店长（门店经理）/ 美容师 | 端口：员工端小程序

---

## 核心链路（员工端视角）

### 场景 A：客户端下单后员工端联动

| 步骤 | 操作 |
|------|------|
| 1 | 收到顾客线下付款申请，执行"确认线下收款" |
| 2 | 进入顾客档案 → 日历视图 |
| 3 | 日历上实时出现标记：该顾客当日消费金额 |

### 场景 B：员工端开单（扫码收款）

| 步骤 | 操作 |
|------|------|
| 1 | 选择顾客，添加服务项目，完成营业额分配 |
| 2 | 系统生成订单二维码，展示在屏幕上 |
| 3 | 若客户选择线下付款则确认收款；若微信支付则自动到账 |
| 4 | 进入顾客档案 → 日历视图，日历实时出现消费标记 |

### 场景 C：服务单提交与完成

**分支一：有预约**

| 步骤 | 操作 |
|------|------|
| 1 | 收到顾客预约通知，进入预约管理，点击「确认预约」 |
| 2 | 顾客到店，点击「顾客已到店」，记录到店时间（预约状态不变） |
| 3 | 提交服务单，系统自动关联该预约记录（`appointment_id`） |
| 4 | 点击「开始服务」，服务单状态进入`服务中` |
| 5 | 服务完成后点击「确认完成」，系统扣减 1 次疗程次数，服务单进入`已完成` |

**分支二：散客直接到店（无预约）**

| 步骤 | 操作 |
|------|------|
| 1 | 顾客到店，员工直接提交服务单，`appointment_id` 留空 |
| 2 | 点击「开始服务」，服务单状态进入`服务中` |
| 3 | 服务完成后点击「确认完成」，系统扣减 1 次疗程次数，服务单进入`已完成` |

## 功能模块

### 3.1 开单（核心功能）

- **权限**：仅店长（门店经理）可开单
- **开单流程**：
  ```
  选择顾客 → 添加项目（疗程卡/院装产品）→ 营业额分配 → 生成订单二维码 → 客户扫码确认付款
  ```
- 开单后生成二维码，客户扫码后在客户端小程序完成支付
- 开单时订单即写入数据库（状态`待支付`），客户扫码后加载同一笔订单进行付款，不重复创建
- 客户可选择微信支付或线下付款
- 线下付款订单需由店长执行"确认收款"后才进入`已支付`
- 开单页展示二维码状态：待扫码 / 已扫码待付款 / 已付款
- 门店未配置店长时，前端直接提示"请先配置门店店长"，不开放"授权员工开单"

#### 项目选择（SPU/SKU）

添加项目时复用与客户端相同的三层商品结构：

1. **左侧品项分类选择器**：品项分类节点（来自 UDT_M_229，21 种可用）；院装产品作为固定末尾节点
2. **右侧 SPU 列表**：展示该分类下的商品卡（名称、价格起步、生美/非生美标签），选定后加入订单行
3. **SKU 规格选择**：点击商品后弹出规格面板，显示全部 SKU（规格名 + 价格）
4. **订单行**：每个 SKU 对应一行，记录 `workfine_item_id`（疗程项目编号或商品编号）、名称、规格、价格、数量

- 同一 SPU 可多次添加不同 SKU（如同时购买 10 次卡和 20 次卡）
- 院装产品 SKU 对应 `UDT_M_341.UDF_M_1870`（商品编号），疗程卡/单品 SKU 对应 `UDT_M_1281/1383.UDF_M_14503`（疗程项目编号）
- SKU 价格从 WorkFine 实时读取，开单时快照存入订单行

> **MVP 简化**：组合套餐开单暂缓；优惠金额、是否赠送功能暂为默认值（开关在 Web 端控制）。

---

### 3.2 营业额分配（核心功能）

开单完成后，店长进行营业额分配：

#### 基本规则

- 先选择部门，再选择该部门下可分配业绩的员工
- 可分配业绩的员工由"是否可分配业绩"字段控制

#### 同部门分配

- 多名美容师参与时，分配总额 ≤ 实收金额
- 可选分配比例：3:7、4:6、5:5、2:8 等

#### 跨部门分配

- 美容部为基础服务部门
- 跨部门时各部门可各按实收金额分配（总额可达实收 2 倍）
- 示例：推广部引流 + 美容部服务 → 各分配 10000 元

#### 默认跳出人员

- 默认顾客下单时指定的美容师（对应订单 `preferred_staff_wf_id`）
- 可选当前门店的所有美容师

---

### 3.3 顾客档案与日历视图（演示重点）

#### 顾客档案

- 展示顾客基本信息、消费记录、绑定门店

#### 日历视图

- 按日展示顾客消费记录
- 每日标记消费金额
- **实时更新**：顾客订单进入`已支付`后日历立即显示消费标记（5 秒内）
- 支持按月浏览
- 同一顾客同一天多笔订单按日汇总金额，可展开查看明细订单
- 入账口径：按`已支付时间`统计，`待支付/待确认收款/支付失败/已关闭`订单不得入账

> 这是会议演示的**核心亮点**，需确保下单→日历标记的实时性和视觉效果。

---

### 3.4 预约管理

#### 预约到服务完成流程

```
预约确认 → 顾客到店 → 提交服务单（关联预约） → 开始服务 → 确认服务完成
```

| 步骤 | 操作 | 状态变更 |
|------|------|---------|
| 1 | 查看待确认预约，点击「确认预约」 | 预约状态：待确认 → 已确认 |
| 2 | 顾客到店，点击「顾客已到店」（记录到店时间，不改预约状态） | — |
| 3 | 提交服务单，系统自动关联该预约记录 | 服务单创建，状态：待服务 |
| 4 | 点击「开始服务」 | 服务单状态：待服务 → 服务中 |
| 5 | 服务完成后点击「确认完成」 | 服务单状态：服务中 → 已完成，扣减 1 次疗程次数 |

#### 服务单与预约的关联关系

- 提交服务单时，`appointment_id` 为**可选**：
  - 有预约：选择关联的预约记录，一条预约对应一张服务单，不可重复创建
  - 无预约（散客直接到店）：`appointment_id` 留空，直接提交服务单
- 服务单关联预约后，预约详情页可直接跳转查看对应服务单

#### 权限

- 店长、被预约美容师均可推进服务状态
- 美容师仅可操作分配给自己的服务单

#### 消息提醒

- 顾客预约后，系统向对应美容师发送预约提醒
- 顾客到店签到后，系统通知美容师「顾客已到店，请准备服务」

---

### 3.5 数据访问权限

| 角色 | 数据访问范围 |
|------|-------------|
| 店长 | 本店所有数据 |
| 美容师 | 本人相关顾客数据 |

- 技师无法看到客户真实电话号码
- 项目部门人员按品项类别查看对应顾客档案

> **MVP 简化**：实现基本角色区分（店长/美容师），细粒度权限配置暂缓。

| 角色 | 权限 |
|------|------|
| 店长（门店经理） | 开单、营业额分配、确认线下收款、查看顾客档案/日历、预约管理 |
| 美容师 | 查看预约、确认服务开始/完成、查看相关顾客信息（不含真实手机号） |

## 状态机

### 订单状态机

```text
待支付 -> 已支付 -> 已完成
待支付 -> 支付失败
待支付 -> 已关闭
待支付 -> 待确认收款 -> 已支付
```

- `已支付`触发：微信支付回调成功，或店长确认线下收款成功
- `待确认收款`：仅用于顾客端选择线下付款后的中间状态

### 服务单状态机

```text
待服务 -> 服务中 -> 已完成
```

- 只有店长或被分配的服务人员可推进状态
- 仅在`服务中 -> 已完成`时扣减 1 次，且剩余次数不得小于 0
- 重复点击"完成服务"时，后端按同一服务单 ID 幂等处理，不得重复扣次

## MVP 验收标准（员工端相关）

1. 订单进入`已支付`后，顾客日历在 **5 秒内**出现当日消费标记
2. WebSocket 断开情况下，员工端在 **30 秒内**通过轮询看到同一笔消费
3. 同一笔订单在日历中仅计入一次（无论重复提交多少次）
4. 同一服务单重复点击"完成服务"不产生重复扣次
5. 美容师不可开单（角色越权操作应被拒绝）
6. 技师不可查看客户完整手机号
7. 开单后 PG 自托管数据库订单表中能查到同一笔记录
8. 完成营业额分配后 PG 自托管数据库营业额分配表中能查到分配明细

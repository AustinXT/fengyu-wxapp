# 客户端（C端）产品需求

> 角色：顾客 | 端口：客户端小程序

---

## 核心链路（客户端视角）

### 场景 A：客户端自助下单

| 步骤 | 操作 |
|------|------|
| 1 | 选择一个服务项目 |
| 2 | 分配美容师 |
| 3 | 提交订单，选择支付方式（微信支付或线下付款） |
| 4 | 微信支付自动确认或等待店长线下确认收款 |

### 场景 B：扫码收款（员工端开单后客户端确认）

| 步骤 | 操作 |
|------|------|
| 1 | 客户微信扫码，打开客户端小程序 |
| 2 | 小程序自动加载订单信息，展示订单详情 |
| 3 | 确认付款，选择支付方式（微信支付或线下付款） |

### 场景 C：预约 → 到店核销 → 疗程卡次数扣减

| 步骤 | 操作 |
|------|------|
| 1 | 进入底部「预约」Tab → 点击「发起预约」→ 选择已支付疗程卡项目、填写期望到店时间、选择美容师（可选）→ 提交预约申请 |
| 2 | 员工端确认预约，预约状态变为`已确认`；预约 Tab 中可查看预约记录及状态 |
| 3 | 顾客到店，员工端提交服务单（关联该预约记录）→ 开始服务 |
| 4 | 员工端确认服务完成 → 疗程卡剩余次数 -1，预约状态变为`已完成` |

## 功能模块

### 2.1 服务/产品浏览

- 展示门店的美容服务和院装产品列表
- 商品展示四层结构：
  - **左侧纵向树状选择器（一级 + 二级）**：
    - 一级节点（可折叠）：生美 ／ 非生美 ／ 院装产品（来自 UDT_M_229.大分类）
    - 二级叶节点（可选中）：各品项分类，来自 WorkFine UDT_M_229，当前 19 种可用：
      - 生美（7种）：蜜语生玑、中华神灸、歆笙泰妍、悠妃曼、安吉丽美颜之爱、美在东方、热敏灸
      - 非生美（7种）：缦之羽、圣源养心、美芯、科颜美、光泽、美卿、恋大
      - 门店自定义（5种）：各门店本地定制品类（以"自定义-"为前缀）
  - **右侧商品列表（三级，SPU 卡片）**：同一商品的不同规格/次数合并为一张卡，展示封面图、名称、价格起步
  - **商品详情页（四级，SKU 规格选择）**：点击商品卡进入详情页，选择具体规格（次数/重量/规格）后方可下单
- 商品列表卡片展示：名称、价格起步、生美/非生美标签、招牌/推荐标记
- 商品详情页展示：名称、描述、全部 SKU 规格选项（规格名 + 价格）、疗程服务次数（疗程卡类）

> **MVP 简化**：组合套餐（促销方案）暂不纳入，树状选择器中不显示"促销方案"分类入口；SPU 商品数据由运营人员在后台录入，首期手动维护。

#### 数据来源

| 商品类型 | WorkFine 表 | 记录数 | 核心字段 |
|----------|------------|--------|---------|
| 可售服务项目（全国统一） | UDT_M_1281 | 481 条 | 疗程项目编号、品项分类、项目名称、疗程服务次数、原价、是否生美 |
| 门店自定义项目 | UDT_M_1383 | 401 条 | 同上，含门店适用范围字段 |
| 院装产品（实体） | UDT_M_341 | 1,940 条 | 商品编号、名称、规格、品牌、产品系列、顾客零售价 |
| 品项分类目录 | UDT_M_229 | 19 种可用 | 项目类型（品项分类）、大分类（生美/非生美） |

- **对接方式**：CloudBase 云函数直连 WorkFine 只读查询（SQL Server）
- **SKU 价格/次数**：运行时从 WorkFine 实时读取，不缓存至 CloudBase
- **SPU 商品元数据**（名称、图片、描述、排序）：存储在 PG 自托管数据库 `product_spu` 表
- **SKU↔WorkFine 映射**：存储在 PG 自托管数据库 `product_spu_sku_map` 表

### 2.2 门店选择

- 首次使用时从门店列表中选择绑定默认门店
- 绑定后默认显示所选门店的服务和产品
- 支持更换绑定门店

#### 数据来源

- **WorkFine 表**：`UDT_M_219`（门店列表子表），主表 `UDT_S_218`，Form 216
- **对接方式**：CloudBase 云函数直连 WorkFine 只读查询
- **查询条件**：`WHERE UDF_M_11956 != '是'`（排除已停止营业的门店）

| 字段名 | 含义 | 说明 |
|--------|------|------|
| UDF_M_437 | 市场 | 市场名称，用于分组展示 |
| UDF_M_438 | **门店名** | **门店唯一标识**，被顾客档案、人事档案、销售单、护理单引用 |
| UDF_M_12033 | 门店所属区域 | 地理区域分类，可用于列表分区 |
| UDF_M_8590 | 可用床位 | 门店接待容量 |
| UDF_M_1777 | 开业时间 | 门店开业日期 |
| UDF_M_11956 | 是否停止营业 | 关店标记，查询时排除值为 `'是'` 的门店 |

> 门店名（`UDF_M_438`）作为跨表字符串外键，贯穿所有业务表（顾客档案 `UDF_S_6443`、人事档案 `UDF_S_1163`、销售单 `UDF_S_349`、护理单 `UDF_S_820`）。小程序选择门店后，需将该门店名持久化到 CloudBase 用户记录。

### 2.3 美容师选择

- 浏览门店美容师列表
- 查看美容师的预约状态（空闲/忙碌）
- 下单时可选择指定美容师（**非必须**）
  - 若指定 → 销售提成归该美容师
  - 若未指定 → 店长后续在 PC 端分配

#### 数据来源

- **WorkFine 表**：`UDT_S_287`（人事档案），Form 264
- **对接方式**：CloudBase 云函数直连 WorkFine 只读查询
- **查询条件**（需同时满足）：
  - 在职：`UDF_S_1624 = '否'`
  - 属于已选门店：`UDF_S_1163 = {已选门店名}`（门店名来自 `UDT_M_219.UDF_M_438`）
  - 美容部员工：`UDF_S_1513 = '美容部'` 或 `UDF_S_1161 = '美容师'`

| 字段名 | 含义 | 说明 |
|--------|------|------|
| UDF_S_1147 | **员工编号** | **主键**，格式 `FY-{YYMMDD}{序号}` |
| UDF_S_1155 | 姓名 | 美容师显示名称 |
| UDF_S_1163 | 所属分院 | 门店名称，用于按已选门店过滤 |
| UDF_S_1161 | 工作职位 | 职位名称（如"美容师"） |
| UDF_S_1513 | 职能部门 | 部门名称（美容部 / 财智部等），过滤条件 |
| UDF_S_1624 | 是否离职 | 枚举：是 / 否，只展示 `'否'` 的员工 |

> **预约状态（空闲/忙碌）**：WorkFine 不存储实时状态，该字段需在 CloudBase 侧通过查询当日有效预约记录动态计算，MVP 阶段可简化为不展示实时状态或展示静态列表。
>
> **主美容师**（2.6 发起预约时默认显示）：来源于顾客档案 `UDT_S_311.UDF_S_6444`（所属美容师字段，存储美容师姓名）。
>
> **提成归属**：下单时选定美容师的员工编号（`UDF_S_1147`）写入订单，映射到 CloudBase 订单记录，供员工端在 `UDT_M_217.UDF_M_2316` 填写营业额分配时使用。

### 2.4 下单与支付

- 选择服务项目后发起下单
- 支付方式：
  - **线下付款**：顾客提交 → 进入`待确认收款` → 店长确认收款 → 进入`已支付`
  - **微信支付**：小程序内支付，回调成功后进入`已支付`
- 下单时需勾选消费协议（MVP 可使用占位文本）
- 订单进入`已支付`后，订单信息实时推送至员工端
- 订单状态集：`待支付` / `待确认收款` / `已支付` / `支付失败` / `已关闭`
- 提交防重：同一订单请求仅允许创建一次（前端防连点 + 后端幂等校验）

> **MVP 简化**：充值卡金抵扣、优惠券、待转金等高级支付功能暂缓。

### 2.6 预约管理

#### 功能概述

顾客可针对已购买且仍有剩余次数的疗程卡发起预约，预约项目直接来自已支付订单的次数余额，无需重复选择服务项目。

#### 发起预约

- 入口：底部「预约」Tab → 「发起预约」按钮
- 顾客填写：期望到店时间段（日期 + 时间段）、指定美容师（可选，默认显示主美容师）
- 预约与订单行强关联，记录来源订单 ID 及具体项目（销售流水号）
- 同一订单行已有`待确认`或`已确认`状态的预约时，不得再次发起

#### 预约列表

- 展示顾客的全部预约记录，按预约时间排序
- 每条记录显示：服务项目名称、来源订单、预约时间、美容师、预约状态
- 支持按状态筛选（全部 / 待确认 / 已确认 / 已取消）

#### 取消预约

- 顾客可取消`待确认`或`已确认`状态的预约
- 取消后剩余次数不变（次数在服务完成时才扣减）

#### 约束规则

- 只有**已支付**且**剩余次数 > 0** 的疗程卡订单行才可发起预约
- 家居产品类订单不进入预约流程
- 预约**不扣减次数**，在员工端确认服务完成后才扣减（与 2.7 到店核销一致）
- 已确认的预约到店后，在「到店服务」流程中可直接关联该预约记录，无需重填项目信息

#### 预约状态机

```text
待确认 -> 已确认 -> 已完成（到店核销完成后自动流转）
待确认 -> 已取消（顾客取消）
已确认 -> 已取消（顾客取消）
```

> **MVP 简化**：预约时段为自由文本输入，不做时段冲突检验；超时自动取消机制暂缓；预约确认/提醒消息通知暂缓，由员工端手动确认。

---

### 2.7 到店服务流程

- 到店后提交服务单（触发疗程卡次数核销）
- 查看服务进行状态（待服务 / 服务中 / 已完成）
- 仅疗程卡类项目进入"到店服务"流程；家居产品支付完成后直接为已完成，不走核销
- 服务状态流转仅允许单向前进，禁止逆向修改
- 服务完成时才扣减疗程卡次数；需保证并发下不出现"重复扣次"

## 状态机

### 订单状态机

```text
待支付 -> 已支付 -> 已完成
待支付 -> 支付失败
待支付 -> 已关闭
待支付 -> 待确认收款 -> 已支付
```

- `待确认收款`：仅用于顾客端选择线下付款后的中间状态
- 疗程卡订单：进入`已支付`后状态为"待服务"，每次服务核销后更新剩余次数
- 家居产品订单：进入`已支付`后可直接置为`已完成`

### 服务单状态机

```text
待服务 -> 服务中 -> 已完成
```

### 预约状态机

```text
待确认 -> 已确认 -> 已完成（到店核销完成后自动流转）
待确认 -> 已取消
已确认 -> 已取消
```

## 疗程卡生命周期（MVP 范围）

```
购买 → 发起预约 → 到店核销（扣次） → 次数归零（完成）
```

| 阶段 | 说明 |
|------|------|
| 购买 | 通过客户端下单购买疗程卡，订单记录总次数、总金额、单次价格 |
| 发起预约 | 从已支付订单的次数余额发起预约，选择到店时间和美容师；预约不扣次 |
| 到店核销 | 顾客到店提交服务单（可关联已有预约）→ 技师确认开始服务 → 确认服务完成 → 剩余次数减 1 |
| 次数归零 | 所有次数消耗完毕，疗程卡状态变为已完成 |
| 剩余次数查询 | 订单详情中展示剩余次数 |

> **MVP 简化**：疗程卡为一次性全额支付，分期回款暂缓。
